У Raku є _множинна диспетчеризація_ на основі сигнатури функції. Завдяки їй кілька функцій можуть мати одну назву. Але вони приймають різні типи вхідних даних. Пишіть декларацію `multi` перед кожним варіантом функції.

```raku
multi sub add(Int $x, Int $y) { $x + $y }
multi sub add(Str $x, Str $y) { $x ~ $y }
```

Після `multi` можна не писати `sub`.

Тут одна й та сама функція має два варіанти. Компілятор дивиться на аргументи в кожному виклику. Потім він вибирає потрібний варіант. Це і є множинна диспетчеризація. Порівняйте ці два виклики:

```raku
say add(10, 20); # 30
say add('10', '20'); # 1020
```

Перший виклик запускає варіант із цілими параметрами. Другий виклик запускає другий варіант. Цей варіант очікує два рядки.

## Літеральні параметри

Ось цікавий випадок. Варіант може мати літеральне значення як параметр. Літерал — це значення прямо в коді, як `42`. Подивіться на ці два варіанти:

```raku
multi sub f(42) {say 'Це відповідь'}
multi sub f($x) {say "$x не є відповіддю"}
```

Raku запускає перший варіант, лише коли аргумент дорівнює саме 42. В усіх інших випадках Raku запускає другий варіант. Порядок двох визначень не має значення.

```raku
f(10); # 10 не є відповіддю
f(42); # Це відповідь
```
