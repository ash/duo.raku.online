Іноді в програмі на Raku щось іде не так. Наприклад, немає потрібного файлу або код викликає `die`. Тоді програма кидає помилку. Таку помилку називають _винятком_. Якщо жоден код не обробляє виняток, програма зупиняється. Так відбувається за замовчуванням. Тут допомагає блок `try`. Це блок коду зі словом `try` перед ним. Код у цьому блоці може не спрацювати. Але програма не падає.

Ви кладете код, який може не спрацювати, у блок `try`. Можливо, код кидає виняток усередині блоку. Тоді блок зупиняється в цьому місці. Але програма працює далі:

```raku
my $result = try {
    die 'Boom!';
};

say "Still works";
```

Блок `try` перехоплює `die`. Тож програма не падає. Вона одразу переходить до наступного оператора. Вона виводить:

```
Still works
```

Тут блок не спрацьовує. Тоді він дає невизначене значення. Тож змінна `$result` невизначена:

```raku
say $result.defined; # False
```

Raku зберігає перехоплений виняток у спеціальній змінній `$!`. Звідти можна прочитати повідомлення винятку:

```raku
say $!.message; # Boom!
```

Отже, `try` допомагає з фатальною помилкою. Без `try` така помилка зупиняє програму. З `try` ваша програма може подивитися на помилку. Потім вона може на неї відреагувати. А якщо блок виконується без винятку? Тоді `$result` містить значення блоку. У цьому разі `$!` невизначена.
