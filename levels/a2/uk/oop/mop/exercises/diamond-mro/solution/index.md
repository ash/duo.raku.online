Ось один спосіб розв'язати задачу.

## Код

```raku
class A {
}

class B is A {
}

class C is A {
}

class D is B is C {
}

say D.^mro.map(*.^name);
```

🦋 Вихідний код можна знайти у файлі [diamond-mro.raku](https://github.com/ash/raku-course/blob/master/exercises/oop/mop/diamond-mro.raku).

## Вивід

```
(D B C A Any Mu)
```

## Коментарі

1. `D` успадковує від двох батьків одночасно. `class D is B is C` має `is` для кожного батька. Це називають множинним успадкуванням. Класи `A`, `B`, `C` і `D` утворюють *ромб*. Від `D` угору до `A` ведуть два шляхи. `A` — батько і для `B`, і для `C`.

1. `.^mro` перетворює ромб на одну пряму лінію. Raku шукає в такому порядку. Першим іде `D`. Потім ідуть його батьки, `B` та `C`. Вони йдуть у тому порядку, що й у коді. Потім іде `A`, спільний батько. Наприкінці йдуть `Any` та `Mu`.

1. І `B`, і `C` ведуть до `A`. Але тип `A` стоїть у списку лише **один раз**. І він іде після них обох. Це мета порядку розв'язання методів. Raku відвідує кожен тип рівно один раз. Батько ніколи не йде перед своєю дитиною. Тож Raku завжди спершу знаходить метод у `B`. Він знаходить його раніше за метод в `A`, який той перевизначає.
