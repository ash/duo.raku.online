Ось один спосіб розв'язати задачу.

## Код

```raku
class Negative is Exception {
    has $.n;

    method message {
        "$.n is negative";
    }
}

sub check($n) {
    Negative.new(n => $n).throw if $n < 0;
    return $n;
}

{
    say check(-5);

    CATCH {
        when Negative {
            say .message;
        }
    }
}

Negative.new(n => -10).throw;
```

🦋 Вихідний код можна знайти у файлі [negative-error.raku](https://github.com/ash/raku-course/blob/master/exercises/oop/custom-exceptions/negative-error.raku).

## Коментарі

1. `Negative is Exception` дозволяє кидати цей клас. Його метод `message` будує текст з атрибута `n`.

1. `check` перевіряє свої вхідні дані. Для від'ємного числа вона кидає власний виняток. Виняток виходить із `check`. Він іде до `CATCH` у блоці, який викликав `check`. Там `when Negative` зіставляється з ним за типом. Потім `CATCH` виводить повідомлення. Це дуже поширене, справжнє застосування власних винятків. Програма перевіряє свої вхідні дані. Для поганого значення вона кидає виняток власного типу.

1. Навіщо навколо виклику стоїть `{ … }`? Фазер `CATCH` обробляє лише винятки з **власного блоку**. Це блок, у якому стоїть цей `CATCH`. Тут блок містить виклик `check(-5)` разом із його `CATCH`. Виклик може не спрацювати, і `CATCH` стоїть там саме для цього. Тож виняток перехоплюється прямо тут. Потім програма йде далі одразу після блоку. А що, як блоку немає? Тоді `CATCH` працює для всієї програми. Він перехоплює виняток. Але потім програма просто завершується. Немає доброго місця, щоб іти далі.

1. Останній рядок, `Negative.new(n => -10).throw`, показує протилежний випадок. Цей рядок стоїть **поза** блоком. Тож виняток ніхто не перехоплює. Виняток іде аж до самого верху. Тоді програма гине, тобто зупиняється з помилкою. Вона виводить повідомлення в стандартний потік помилок. Також вона виводить туди трасування стека. Трасування стека показує, де в коді сталася помилка. Потім програма завершується, і її код завершення не дорівнює `0`. Так стається з кожним винятком, який ви не перехоплюєте. І тому для першого кидання потрібен був `CATCH`. Без нього програма не може йти далі.
