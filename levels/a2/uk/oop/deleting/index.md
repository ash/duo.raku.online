`spurt` і `mkdir` створюють щось на диску. Дві інші підпрограми видаляють це з диска.

Підпрограма `unlink` видаляє файл:

```raku
spurt 'temp.txt', 'scratch data';
say 'temp.txt'.IO.e; # True

unlink 'temp.txt';
say 'temp.txt'.IO.e; # False
```

`unlink` видаляє файл із вказаним ім'ям. Як і інші підпрограми файлової системи, `unlink` — це також і метод. Ви викликаєте його для об'єкта шляху: `'temp.txt'.IO.unlink`.

Видалення відбувається відразу, і це назавжди. Кошика для сміття немає. Ви не можете повернути файл. Зверніть увагу ще на одне. Після видалення файлу перевіряйте його через `.e`. Цей метод перевіряє, чи існує шлях. Не використовуйте тут `.f`. Перевірки `.f` і `.d` перевіряють тип шляху. Вони дають помилку, коли шляху немає.

Підпрограма `rmdir` видаляє каталог. Але каталог має бути **порожнім**:

```raku
mkdir 'reports';
rmdir 'reports';
say 'reports'.IO.e; # False
```

Якщо каталог не порожній, `rmdir` нічого не видаляє. Каталог лишається на місці. Тож каталог із файлами ви видаляєте у два кроки. Спочатку ви робите його порожнім. Потім ви видаляєте його:

```raku
mkdir 'reports';
spurt 'reports/jan.txt', 'January';
spurt 'reports/feb.txt', 'February';

.unlink for 'reports'.IO.dir;   # видалити кожен запис
rmdir 'reports';                # тепер каталог порожній
say 'reports'.IO.e;             # False
```

`'reports'.IO.dir` дає список записів у каталозі. Ви бачили це в попередній темі. Програма викликає `.unlink` для кожного запису. Це видаляє їх усі. Тепер каталог порожній. Тож `rmdir` може його видалити. Цей простий цикл чекає в каталозі тільки файли. Але в каталозі можуть бути й інші каталоги. Тоді спочатку треба спорожнити кожен внутрішній каталог. Ви робите це так само.
