Виняток від `die` одразу зупиняє все. Іноді це занадто. Можливо, підпрограма не може дати результат. Вона має повідомити про цю проблему. Але викликач має вирішити, чи зупиняється програма. Викликач — це код, який викликав підпрограму. Для такого випадку в Raku є _м'які збої_. Ви створюєте їх через `fail`.

Підпрограма може викликати `fail`. Тоді вона не кидає виняток одразу. Натомість вона повертає викликачеві особливий об'єкт `Failure`. `Failure` — це значення з помилкою всередині. Він невизначений. Тож викликач може тихо його перевірити:

```raku
sub divide($a, $b) {
    fail 'cannot divide by zero' if $b == 0;
    return $a / $b;
}

say divide(10, 2);         # 5
say divide(10, 0).defined; # False
```

Перший виклик спрацьовує й повертає `5`. Другий виклик не спрацьовує. Він повертає `Failure`. Для цього об'єкта `defined` дає `False`. Тож викликач може перевірити результат, перш ніж його використати.

Чому `Failure` називають _м'яким_? Він стає справжнім, кинутим винятком лише в одному випадку. Це коли ви використовуєте його як значення без перевірки. Але ви можете його обробити, наприклад, перевіркою `defined`. Тоді він лишається тихим. Тож підпрограма може повідомити про проблему. Уся програма не мусить зупинятися.

## Ви це вже знаєте

Такий збій відкладається на потім. Так працює не лише `fail`. Раніше в цій частині ви двічі бачили ту саму ідею.

**Ділення на нуль** тихо створює значення. Значення кидає виняток, лише коли ви справді його використовуєте:

```raku
my $x = 1 / 0;   # помилки ще немає
say $x;           # кидає лише тут, коли значення використано
```

**Зовнішня програма, яка не спрацювала,** повертає `Proc`. Він кидає виняток лише в одному випадку. Це коли ви викидаєте `Proc` і не обробляєте його. Збережіть `Proc` і подивіться на нього. Тоді він лишається тихим значенням:

```raku
run 'sh', '-c', 'exit 1';   # невдалий Proc відкинуто, тож це кидає виняток
```

У кожному випадку проблема не зупиняє програму одразу. Вона стає значенням. Це значення можна перевірити. Воно стає кинутим винятком лише у двох випадках. Ви використовуєте його без перевірки, або ви його ігноруєте. Тема [Не кожна помилка негайна](/uk/oop/try/deferred-errors) показує обидва приклади разом.
