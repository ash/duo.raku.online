Модуль `Test` має не лише `ok` та `is`. У ньому є порівняння для різних видів значень. Ось найкорисніші з них:

* `is` — перевіряє, що два значення рівні (як рядки чи числа)
* `is-deeply` — перевіряє, що дві структури даних точно рівні, і їхні типи теж
* `like` — перевіряє, що рядок збігається з регулярним виразом
* `isnt` — проходить, коли два значення **не** рівні

Використовуйте `is-deeply` для масивів, хешів і даних усередині інших даних. Він точно порівнює структуру і тип:

```raku
use Test;

my @reversed = (1, 2, 3).reverse;
is-deeply @reversed, [3, 2, 1], 'reversed';

done-testing;
```

Це виводить:

```
ok 1 - reversed
1..1
```

`is` перетворює значення на рядки. Потім він порівнює їх, але не дуже строго. `is-deeply` працює інакше. З ним структури мають справді збігатися. Зверніть увагу, що `done-testing` ставить план `1..1` у кінці, після перевірки.

`done-testing` може порахувати тести за вас. Але ви також можете вказати їхню кількість на початку, через `plan`. Це допомагає з однією проблемою. Іноді файл тестів зупиняється надто рано. Тоді він пропускає деякі перевірки без жодного повідомлення:

```raku
use Test;

plan 2;
ok True,  'first';
ok 1 < 2, 'second';
```

Тепер план стоїть **першим**. Він іде перед результатами:

```
1..2
ok 1 - first
ok 2 - second
```

Тут видно, чим `plan` відрізняється від `done-testing`. `plan` виводить кількість `1..2` угорі, до всіх перевірок. `done-testing` виводить її в самому кінці. У будь-якому разі з `plan 2` запуск чекає рівно двох тестів. Якщо запускається менше або більше тестів, увесь набір тестів провалюється. Використовуйте `plan`, якщо кількість тестів не змінюється і ви її знаєте. Використовуйте `done-testing`, якщо простіше дати модулю тестів порахувати їх.
