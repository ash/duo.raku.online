Щоб отримати інструменти для тестів, напишіть `use Test`. Найпростіша перевірка — це `ok`. Вона проходить, коли її умова істинна. Кожна перевірка також може мати опис:

```raku
use Test;

ok 1 == 1, 'one equals one';
ok 2 > 1,  'two is greater';

done-testing;
```

Запустіть цю програму. Вона виводить результат у стандартному форматі для тестів. Цей формат називається _TAP_:

```
ok 1 - one equals one
ok 2 - two is greater
1..2
```

Для кожної перевірки, яка проходить, ви бачите `ok` з її номером та описом. Перевірка, яка не проходить, показує `not ok`. Останній рядок, `1..2`, — це _план_. Він каже, скільки тестів виконалося. Виклик `done-testing` у кінці виводить цей план автоматично.

Іноді ви очікуєте певне значення. Тоді `is` зрозуміліший за `ok`. Якщо тест не проходить, `is` показує два значення. Він показує значення, яке ви очікуєте, і значення, яке ви отримуєте:

```raku
use Test;

is 2 + 2, 4, 'addition works';

done-testing;
```

Це виводить `ok 1 - addition works`. Тепер подивімося, як `is` повідомляє про невдачу. Дайте `is` неправильне очікуване значення:

```raku
use Test;

is 2 + 2, 5, 'addition works';

done-testing;
```

Тепер перевірка не проходить. Вивід точно показує, що не так:

```
not ok 1 - addition works
# Failed test 'addition works'
# at test.raku line 3
# expected: '5'
#      got: '4'
1..1
# You failed 1 test of 1
```

Рядок `not ok` показує невдачу. Під ним інші рядки пояснюють проблему. Вони показують значення, яке ви очікуєте, і значення, яке ви отримуєте. Тож коли вам потрібне певне значення, `is` допомагає більше, ніж просто `ok`.

З `ok`, `is` і `done-testing` ви вже можете написати корисний файл тестів. Наступна тема показує [інші порівняння](/uk/advanced/testing/comparisons).
