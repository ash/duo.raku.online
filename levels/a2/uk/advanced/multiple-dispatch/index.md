У частині «Основи» ви дізналися про [_мульти-функції_](/uk/essentials/more-on-functions/multi-functions). Це кілька підпрограм з однаковим іменем. Raku дивиться на типи аргументів. Потім він вибирає потрібну підпрограму. Це називають _множинною диспетчеризацією_.

Досі Raku вибирав за _типом_ аргументів. З реченням `where` можна зробити більше. Raku може вибирати ще й за _значенням_. Ви пишете `where` після параметра. У ньому є умова. Кожен варіант функції називають кандидатом. Raku вибирає кандидата, лише коли його умова істинна для аргументу:

```raku
multi sub info(Int $n where $n < 0)  { say "$n is negative" }
multi sub info(Int $n where $n == 0) { say "$n is zero" }
multi sub info(Int $n where $n > 0)  { say "$n is positive" }

info(-5);
info(0);
info(7);
```

Кожен виклик іде до кандидата з істинною умовою для цього значення:

```
-5 is negative
0 is zero
7 is positive
```

Подивіться на типи. Усі три кандидати мають однакову сигнатуру: один `Int`. Без речень `where` вони конфліктують. Raku не може вибрати між ними. Умови роблять їх різними.

## Як зупинити рекурсію

Часто `where` використовують із рекурсією. У рекурсії функція викликає саму себе. У якийсь момент вона мусить зупинитися. Цю точку зупинки можна винести в окремого кандидата. Ось знову факторіал. Тепер у нього дві мульти-підпрограми:

```raku
multi sub fact(Int $n where $n <= 1) { 1 }
multi sub fact(Int $n)               { $n * fact($n - 1) }

say fact(5); # 120
```

Перший кандидат — це базовий випадок. Тут рекурсія зупиняється. У цьому випадку `$n` дорівнює `1` або менше. Цей кандидат просто повертає `1`. Усі інші значення йдуть до другого кандидата. Він знову викликає `fact` із меншим числом. Усередині функції немає `if`. Диспетчер вибирає між базовим випадком і рекурсивним кроком. Диспетчер — це частина Raku, яка вибирає кандидата.
