Є ще два префікси. Вони виконують код заради того, що він робить. Значення коду не важливе.

Префікс `sink` виконує код у _контексті стоку_. Код виконується лише заради побічних ефектів. Raku викидає результат. Це корисно з лінивою операцією. З `sink` ви змушуєте її виконатися:

```raku
sink (1..3).map({ print "$_ " });
print "\n"; # 1 2 3
```

Тут ми виконуємо `map` лише заради друку. `sink` дбає, щоб він справді виконався. Потім `sink` викидає список від `map`. Якщо ніщо його не змушує, лінивий `map` може взагалі не виконатися. Так буває, коли ніхто не використовує його результат.

Префікс `quietly` виконує блок і **ховає його попередження**. Деякий код зазвичай друкує попередження в потік помилок. Усередині `quietly` цей код мовчить:

```raku
my $value;
quietly {
    say $value + 1; # 1, без попередження "uninitialized value"
}
```

Зазвичай Raku показує попередження, коли ви додаєте `1` до невизначеного `$value`. Це попередження про «неініціалізоване значення». Усередині `quietly` це попередження приховане. Іноді ви знаєте, що ваш код дає попередження. Вам не потрібен цей шум. Тоді використовуйте `quietly`. Але не використовуйте його часто. Попередження зазвичай показує справжню помилку.
