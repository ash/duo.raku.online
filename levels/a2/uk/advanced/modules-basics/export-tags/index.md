Позначте підпрограму як `is export`. Тоді вона потрапляє до _типової_ групи експорту модуля. Простий `use` приносить імена з цієї групи. Також ви можете дати `is export` _мітку_. З мітками ви розкладаєте експорти по групах з іменами. Тоді кожна програма бере ту групу, яку хоче.

Ви пишете мітку в дужках після `is export`:

```raku
unit module Greeting;

sub hello($name)   is export            { "Hello, $name!" }
sub goodbye($name) is export(:partings) { "Goodbye, $name!" }
```

`hello` не має мітки. Тож вона належить до типової групи. `goodbye` має мітку `:partings`.

Простий `use` імпортує лише типову групу:

```raku
use Greeting;      # hello доступна; goodbye ні
```

Тепер назвіть мітку. Тоді `use` імпортує натомість цю групу. Це може вас здивувати. Типову групу він при цьому _не_ імпортує:

```raku
use Greeting :partings; # goodbye доступна; hello ні
```

З `:partings` ви отримуєте саме цю групу. Хочете всі експорти модуля? Тоді використайте вбудовану мітку `:ALL`:

```raku
use Greeting :ALL; # і hello, і goodbye
```

Дві особливі мітки добре знати. Кожен модуль підтримує `:ALL`. Вона імпортує всі експорти модуля. Ви можете поставити `:MANDATORY` на підпрограму. Тоді підпрограма імпортується завжди. Неважливо, яку мітку вибирає програма.

Насправді кожна мітка — це пакунок. Він лежить усередині пакунка `EXPORT` модуля. Приклад — `Greeting::EXPORT::partings`. [Інтроспекція модулів](/uk/advanced/module-introspection) перелічує саме ці пакунки. З мітками великий модуль може тримати типову групу малою. А програма все одно може попросити більше можливостей.
