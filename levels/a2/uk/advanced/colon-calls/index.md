Зазвичай аргументи методу чи підпрограми стоять у дужках: `@a.grep(* > 5)`. У Raku є другий спосіб. Поставте після імені **двокрапку**. Усе після двокрапки стає списком аргументів. Дужки зовсім не потрібні:

```raku
say (1..10).grep: * %% 2; # (2 4 6 8 10)
```

Двокрапка в `grep:` робить ту саму роботу, що й дужки. `(1..10).grep: * %% 2` означає точно те саме, що `(1..10).grep(* %% 2)`. Можна використовувати будь-яку з двох форм:

```raku
say <a b c>.join('-'); # a-b-c
say <a b c>.join: '-'; # a-b-c
```

Форма з двокрапкою найкраще підходить для деяких методів. Вони приймають **блок** або вираз [Whatever](/uk/advanced/whatever). Двокрапка прибирає один рівень дужок. Порівняйте:

```raku
my @a = 3, 1, 2;

say @a.sort({ $^b <=> $^a }); # дужки навколо блоку
say @a.sort: { $^b <=> $^a }; # двокрапка — закривальну дужку шукати не треба
```

Обидва рядки виводять `(3 2 1)`. Але версію з двокрапкою легше читати. З довгим блоком це ще помітніше.

Ви вже знаєте виклики без дужок. Ви використовуєте їх зі списковими операторами, як-от `say 1, 2, 3`. Там `say` бере все після себе як свої аргументи. Форма з двокрапкою — та сама ідея для методів. Запам'ятайте одне правило. Форма з двокрапкою бере **решту оператора** як аргументи. Тож вона мусить стояти в **кінці** ланцюжка викликів. Ось чому працює `('a' .. 'z')».uc».ord.grep: 60 < * < 70`. `grep` — останній виклик. Після нього в ланцюжку нічого немає. Вам треба викликати ще методи? Тоді використайте форму з дужками. Або згрупуйте частини всього виразу дужками. Так код стане зрозумілим:

```raku
say (('a' .. 'z')».uc».ord.grep: 60 < * < 70)».chr # (A B C D E)
```

Зверніть увагу на одну річ. Не використовуйте двокрапку **й** дужки разом, як-от `.grep:( … )`. У Raku `:( … )` означає інше. Це сигнатура, записана як значення. Тож Raku не може прочитати цей код. Використовуйте або `.grep( … )`, або `.grep: …`. Беріть щось одне, а не обидва.
