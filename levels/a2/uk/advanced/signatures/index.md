У частині «Основи» ви [писали підпрограми](/uk/essentials/functions). Вони мали позиційні та іменовані параметри. Параметри мали типові значення. Список параметрів — це _сигнатура_. Цей розділ показує ще дві речі, які вміє сигнатура. Вона може зробити параметр необов'язковим. А ще вона може збирати будь-яку кількість зайвих аргументів.

## Необов'язкові параметри

Параметр зі знаком питання після нього — _необов'язковий_. Той, хто викликає, може його пропустити. Тоді параметр невизначений. Тож ви можете дати значення на заміну. Використайте для цього оператор «визначене або» `//`:

```raku
sub greet($name, $greeting?) {
    my $g = $greeting // 'Hello';
    say "$g, $name!";
}

greet('Anna');           # Hello, Anna!
greet('Anna', 'Hi');     # Hi, Anna!
```

Тут ми викликаємо `greet` з одним аргументом. Тоді `$greeting` невизначений. Тож `//` дає замість нього `'Hello'`.

## Всеїдні параметри

Параметр із `*` — _всеїдний_. Він бере всі аргументи, що лишилися. Ви записуєте всеїдний масив як `*@`. Він збирає будь-яку кількість позиційних аргументів у масив:

```raku
sub count-them(*@items) {
    say @items.elems;
}

count-them(1, 2, 3, 4); # 4
count-them('a', 'b');   # 2
```

Можна використовувати звичайні параметри разом із всеїдним. Спочатку сталі параметри отримують свої значення. Усе інше йде у всеїдний масив:

```raku
sub titles($name, *@titles) {
    say "$name has {@titles.elems} title(s)";
}

titles('Anna', 'Dr', 'Prof'); # Anna has 2 title(s)
```

Всеїдний хеш працює так само. Ви записуєте його як `*%`. Він збирає всі зайві іменовані аргументи в хеш:

```raku
sub register($name, *%options) {
    say "$name: {%options.elems} option(s)";
    say "role is %options<role>";
}

register('Anna', role => 'admin', active => True);
```

Два іменовані аргументи стають ключами `%options`. Тож програма виводить:

```
Anna: 2 option(s)
role is admin
```
