Є ще два контексти. Вони вирішують одне питання. Значення — це **список** із кількох значень? Чи це один-єдиний **елемент**? Сигіли `@` і `$` показують цю різницю.

У _списковому контексті_ масив стає окремими елементами. Цикл `for` ставить свій аргумент у списковий контекст. Тож цикл проходить по кожному елементу:

```raku
my @a = 1, 2, 3;

my $count = 0;
$count++ for @a;
say $count; # 3
```

У _штучному контексті_ той самий масив — це одне значення. Контекстуалізатор `$( … )` задає штучний контекст. Тепер цикл бачить лише одну річ. Тож він виконується один раз:

```raku
my @a = 1, 2, 3;

my $count = 0;
$count++ for $(@a);
say $count; # 1
```

Штучний контекст пояснює і ось що. Ви присвоюєте масив скаляру. Скаляр отримує весь масив як один елемент. Він не копіює елементи. Причина в тому, що `my $x = @a` ставить `@a` у штучний контекст. Зверніть увагу, що цей один елемент може бути іншим контейнером. А в цьому контейнері може бути багато елементів:

```raku
my @a = 1, 2, 3;

my $var = @a;
say $var;      # [1 2 3]
say $var.WHAT; # (Array)
```

`$var` — це скалярний контейнер. Тож тепер він зберігає один об'єкт. Цей об'єкт — `Array`. Це легко перевірити. Використайте `$var` як своєрідне посилання на масив. Так це називають в інших мовах:

```raku
say $var[1]; # 2
```

Контекстуалізатор `@( … )` робить протилежне. Він задає списковий контекст.

Є ще _контекст стоку_ (sink context). У контексті стоку ніхто не використовує значення оператора. Raku просто викидає це значення. Наприклад, рядок коду може існувати лише заради побічного ефекту. Побічний ефект — це додаткова дія коду, як-от виведення. Іноді значення в контексті стоку не робить нічого корисного. Тоді Raku може попередити вас про «useless use». Це корисна підказка. Мабуть, ви забули використати результат.

Сигіл, `$` або `@`, — це насправді вибір контексту. Іноді вам потрібен інший контекст. Тоді контекстуалізатори `$( )` та `@( )` змінюють його.
