В Raku есть _множественная диспетчеризация_ по сигнатуре функции. С ней у нескольких функций может быть одно имя. Но они принимают разные типы входных данных. Пишите декларатор `multi` перед каждым вариантом функции.

```raku
multi sub add(Int $x, Int $y) { $x + $y }
multi sub add(Str $x, Str $y) { $x ~ $y }
```

После `multi` можно не писать `sub`.

Здесь у одной функции два варианта. Компилятор смотрит на аргументы в каждом вызове. Потом он выбирает нужный вариант. Это и есть множественная диспетчеризация. Сравните эти два вызова:

```raku
say add(10, 20); # 30
say add('10', '20'); # 1020
```

Первый вызов запускает вариант с целочисленными параметрами. Второй вызов запускает второй вариант. Этот вариант ожидает две строки.

## Литеральные параметры

Вот интересный случай. Параметром варианта может быть литеральное значение. Литерал — это значение прямо в коде, например `42`. Посмотрите на эти два варианта:

```raku
multi sub f(42) {say 'Это ответ'}
multi sub f($x) {say "$x не является ответом"}
```

Raku запускает первый вариант, только когда аргумент равен ровно 42. Во всех других случаях Raku запускает второй вариант. Порядок двух определений не важен.

```raku
f(10); # 10 не является ответом
f(42); # Это ответ
```
