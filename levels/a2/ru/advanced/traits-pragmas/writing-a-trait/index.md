Типажи — это обычные мультиподпрограммы с особым именем. Поэтому вы можете писать свои типажи. Вам нужен типаж `is something`? Тогда определите `multi sub trait_mod:<is>`. Его параметры говорят две вещи. Они говорят, с чем работает типаж. Ещё они задают имя типажа:

Это одна из трудных частей Raku. Не волнуйтесь, если это кажется сложным. Вы можете хорошо использовать встроенные типажи и без этих знаний. Вам не нужно знать, как они сделаны. Вам редко понадобится самому писать типаж. Эта страница просто показывает, как типажи работают внутри.

```raku
my @traced;

multi sub trait_mod:<is>(Routine:D $r, :$traced!) {
    @traced.push($r.name);
}

sub foo() is traced { }
sub bar() is traced { }

say @traced; # [foo bar]
```

Посмотрите на сигнатуру. Первый параметр — `Routine:D $r`. Это то, у чего есть типаж. Здесь это подпрограмма. `:D` — это типовой _смайлик_. Ему нужно **определённое** значение. Это настоящий объект подпрограммы. Это не сам неопределённый тип `Routine`. Есть ещё два смайлика. `:U` требует неопределённый объект типа. `:_` принимает и то, и другое. Именованный параметр `:$traced!` — это имя типажа. Из-за этого параметра `is traced` вызывает эту подпрограмму. Типажи выполняются во время **компиляции**. Поэтому Raku записывает `foo` и `bar` сразу, когда читает их объявления. Когда программа работает, в `@traced` уже есть оба имени. Можно даже передвинуть строку `say @traced` вверх, выше двух определений `sub`. Она всё равно напечатает `[foo bar]`.

Этот маленький типаж только записывает имена. Но та же идея может делать гораздо больше. Например, типаж может обернуть подпрограмму и добавить логирование. Он может проверить атрибут. Или он может прикрепить метаданные, то есть дополнительные данные о коде. Здесь первый параметр — `Routine`. Можно также сделать его `Attribute` или `Variable`. Тогда типаж работает с атрибутами или переменными. Типажи оставляют синтаксис объявлений в Raku открытым. Вы всегда можете добавить новые типажи. Встроенный `is rw` и ваш собственный `is traced` сделаны одинаково.
