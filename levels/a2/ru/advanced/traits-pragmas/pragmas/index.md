_Прагма_ похожа на модуль. Вы загружаете её с помощью `use`. Но она не добавляет новый код. Вместо этого она меняет правило компиляции. Изменение действует до конца текущей области видимости. Вы включаете прагму с помощью `use`. Если это имеет смысл, её можно выключить с помощью `no`.

Самая важная прагма — `strict`. В Raku она **включена по умолчанию**. С ней вы должны объявлять каждую переменную до её использования. Поэтому Raku находит опечатки в именах переменных. Неправильное имя не создаёт тихо новую переменную.

`no strict` выключает `strict`. Тогда этого правила больше нет. Теперь можно присвоить значение переменной без `my`:

```raku
no strict;

$x = 42;
say $x; # 42
```

С обычной `strict` такое `$x = 42` без `my` — ошибка. Raku показывает её во время компиляции: *Variable '$x' is not declared*. Строка `no strict` выключает это правило. Это действует до конца области видимости.

Есть и другие прагмы. `fatal` заставляет тихую ошибку выбрасывать исключение. Это полезно, когда вы узнаете, как обрабатывать исключения. `isms` разрешает некоторые привычные способы писать код из других языков. `variables` меняет правила для переменных. Действие прагмы _лексическое_. Оно работает только до конца её блока. Так что вы можете сделать правило строже или мягче. Вы можете сделать это ровно там, где нужно в коде.

Одна прагма принимает аргумент. Это `lib`. Raku ищет модули в списке каталогов. `lib` добавляет каталог в этот список. Она работает как параметр командной строки `-I`. Но вы пишете её внутри программы:

```raku
use lib 'lib';
```

Она понадобится вам, когда вы будете писать и загружать свои [модули](/ru/advanced/modules-basics/using-modules).
