В разделе «Основы» вы узнали о [_мульти-функциях_](/ru/essentials/more-on-functions/multi-functions). Это несколько подпрограмм с одним именем. Raku смотрит на типы аргументов. Потом он выбирает нужную подпрограмму. Это называется _множественная диспетчеризация_.

До сих пор Raku выбирал по _типу_ аргументов. С конструкцией `where` можно сделать больше. Raku может выбирать и по _значению_. Вы пишете `where` после параметра. В `where` стоит условие. Каждый вариант функции называется кандидатом. Raku выбирает кандидата, только когда его условие истинно для аргумента:

```raku
multi sub info(Int $n where $n < 0)  { say "$n is negative" }
multi sub info(Int $n where $n == 0) { say "$n is zero" }
multi sub info(Int $n where $n > 0)  { say "$n is positive" }

info(-5);
info(0);
info(7);
```

Каждый вызов попадает к кандидату с истинным условием для этого значения:

```
-5 is negative
0 is zero
7 is positive
```

Посмотрите на типы. У всех трёх кандидатов одна и та же сигнатура: один `Int`. Без конструкций `where` они конфликтуют. Raku не может выбрать между ними. Условия делают их разными.

## Как остановить рекурсию

`where` часто используют с рекурсией. В рекурсии функция вызывает сама себя. В какой-то момент она должна остановиться. Эту точку остановки можно вынести в отдельного кандидата. Вот снова факториал. Теперь в нём две мульти-подпрограммы:

```raku
multi sub fact(Int $n where $n <= 1) { 1 }
multi sub fact(Int $n)               { $n * fact($n - 1) }

say fact(5); # 120
```

Первый кандидат — это базовый случай. Здесь рекурсия останавливается. В этом случае `$n` равно `1` или меньше. Этот кандидат просто возвращает `1`. Все остальные значения идут ко второму кандидату. Он снова вызывает `fact` с меньшим числом. Внутри функции нет `if`. Диспетчер выбирает между базовым случаем и шагом рекурсии. Диспетчер — это часть Raku, которая выбирает кандидата.
