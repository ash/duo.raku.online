Чтобы получить инструменты для тестов, напишите `use Test`. Самая простая проверка — это `ok`. Она проходит, когда её условие истинно. У каждой проверки может быть ещё и описание:

```raku
use Test;

ok 1 == 1, 'one equals one';
ok 2 > 1,  'two is greater';

done-testing;
```

Запустите эту программу. Она печатает результат в стандартном формате для тестов. Этот формат называется _TAP_:

```
ok 1 - one equals one
ok 2 - two is greater
1..2
```

Для каждой проверки, которая прошла, вы видите `ok` с её номером и описанием. Проверка, которая не прошла, показывает `not ok`. Последняя строка, `1..2`, — это _план_. Он говорит, сколько тестов запустилось. Вызов `done-testing` в конце печатает этот план сам.

Иногда вы ждёте определённое значение. Тогда `is` понятнее, чем `ok`. Если тест не проходит, `is` показывает два значения. Он показывает значение, которое вы ждёте, и значение, которое вы получаете:

```raku
use Test;

is 2 + 2, 4, 'addition works';

done-testing;
```

Эта программа печатает `ok 1 - addition works`. Теперь посмотрим, как `is` сообщает об ошибке. Дайте `is` неверное ожидаемое значение:

```raku
use Test;

is 2 + 2, 5, 'addition works';

done-testing;
```

Теперь проверка не проходит. Вывод точно показывает, что не так:

```
not ok 1 - addition works
# Failed test 'addition works'
# at test.raku line 3
# expected: '5'
#      got: '4'
1..1
# You failed 1 test of 1
```

Строка `not ok` показывает ошибку. Под ней другие строки объясняют проблему. Они показывают значение, которое вы ждёте, и значение, которое вы получаете. Поэтому, когда вам нужно определённое значение, `is` помогает больше, чем просто `ok`.

С `ok`, `is` и `done-testing` вы уже можете написать полезный тестовый файл. Следующая тема показывает [другие виды сравнений](/ru/advanced/testing/comparisons).
