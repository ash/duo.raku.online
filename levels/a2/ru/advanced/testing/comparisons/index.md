В модуле `Test` есть не только `ok` и `is`. В нём есть сравнения для разных видов значений. Вот самые полезные:

* `is` — проверяет, что два значения равны (как строки или числа)
* `is-deeply` — проверяет, что две структуры данных точно равны, и их типы тоже
* `like` — проверяет, что строка подходит под регулярное выражение
* `isnt` — проходит, когда два значения **не** равны

Используйте `is-deeply` для массивов, хэшей и данных внутри других данных. Он точно сравнивает структуру и тип:

```raku
use Test;

my @reversed = (1, 2, 3).reverse;
is-deeply @reversed, [3, 2, 1], 'reversed';

done-testing;
```

Вывод:

```
ok 1 - reversed
1..1
```

`is` превращает значения в строки. Потом он сравнивает их, но не очень строго. `is-deeply` работает иначе. С ним структуры должны совпадать по-настоящему. Заметьте, что `done-testing` ставит план `1..1` в конец, после проверки.

`done-testing` может посчитать тесты за вас. Но вы можете и указать их число в начале, с помощью `plan`. Это помогает с одной проблемой. Иногда тестовый файл останавливается слишком рано. Тогда он пропускает некоторые проверки без всякого сообщения:

```raku
use Test;

plan 2;
ok True,  'first';
ok 1 < 2, 'second';
```

Теперь план стоит **первым**. Он идёт перед результатами:

```
1..2
ok 1 - first
ok 2 - second
```

Здесь вы видите, чем `plan` отличается от `done-testing`. `plan` печатает количество `1..2` вверху, до всех проверок. `done-testing` печатает его в самом конце. В любом случае с `plan 2` запуск ждёт ровно два теста. Если запускается меньше или больше тестов, весь набор тестов не проходит. Используйте `plan`, если число тестов постоянное и вы его знаете. Используйте `done-testing`, если проще дать модулю тестов посчитать самому.
