Обычно аргументы метода или подпрограммы стоят в скобках: `@a.grep(* > 5)`. В Raku есть второй способ. Поставьте **двоеточие** после имени. Всё после двоеточия становится списком аргументов. Скобки совсем не нужны:

```raku
say (1..10).grep: * %% 2; # (2 4 6 8 10)
```

Двоеточие в `grep:` делает ту же работу, что и скобки. `(1..10).grep: * %% 2` значит ровно то же, что `(1..10).grep(* %% 2)`. Можно использовать любую форму:

```raku
say <a b c>.join('-'); # a-b-c
say <a b c>.join: '-'; # a-b-c
```

Форма с двоеточием удобнее всего с некоторыми методами. Они принимают **блок** или выражение [Whatever](/ru/advanced/whatever). Двоеточие убирает один уровень скобок. Сравните:

```raku
my @a = 3, 1, 2;

say @a.sort({ $^b <=> $^a }); # скобки вокруг блока
say @a.sort: { $^b <=> $^a }; # двоеточие -- нет закрывающей скобки
```

Обе строки выводят `(3 2 1)`. Но версию с двоеточием легче читать. С длинным блоком это ещё заметнее.

Вы уже знаете вызовы без скобок. Вы используете их со списковыми операторами, например `say 1, 2, 3`. Там `say` берёт как аргументы всё после себя. Форма с двоеточием — та же идея для методов. Запомните одно правило. Форма с двоеточием берёт как аргументы **остаток выражения**. Поэтому она должна стоять в **конце** цепочки вызовов. Именно поэтому работает `('a' .. 'z')».uc».ord.grep: 60 < * < 70`. `grep` — последний вызов. После него в цепочке ничего нет. Нужно вызвать ещё методы? Тогда используйте форму со скобками. Или сгруппируйте части всего выражения скобками. Так код станет понятным:

```raku
say (('a' .. 'z')».uc».ord.grep: 60 < * < 70)».chr # (A B C D E)
```

Будьте осторожны с одной вещью. Не пишите двоеточие **и** скобки вместе, как в `.grep:( … )`. В Raku `:( … )` значит другое. Это сигнатура, записанная как значение. Поэтому Raku не может прочитать этот код. Пишите либо `.grep( … )`, либо `.grep: …`. Выберите одно из них, не оба.
