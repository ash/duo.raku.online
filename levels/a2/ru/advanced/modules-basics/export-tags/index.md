Пометьте подпрограмму как `is export`. Тогда она попадает в группу экспорта модуля _по умолчанию_. Простой `use` подключает имена из этой группы. Ещё можно дать `is export` _тег_. С тегами вы раскладываете экспорты по группам с именами. Тогда каждая программа берёт ту группу, которую хочет.

Тег пишут в скобках после `is export`:

```raku
unit module Greeting;

sub hello($name)   is export            { "Hello, $name!" }
sub goodbye($name) is export(:partings) { "Goodbye, $name!" }
```

У `hello` нет тега. Поэтому она в группе по умолчанию. У `goodbye` есть тег `:partings`.

Простой `use` импортирует только группу по умолчанию:

```raku
use Greeting;      # hello is available; goodbye is not
```

Теперь укажите тег. Тогда `use` импортирует вместо этого группу тега. Это может вас удивить. Он _не_ импортирует заодно и группу по умолчанию:

```raku
use Greeting :partings; # goodbye is available; hello is not
```

С `:partings` вы получаете ровно эту группу. Хотите все экспорты модуля? Тогда используйте встроенный тег `:ALL`:

```raku
use Greeting :ALL; # both hello and goodbye
```

Полезно знать два особых тега. Каждый модуль поддерживает `:ALL`. Он импортирует все экспорты модуля. Вы можете поставить `:MANDATORY` на подпрограмму. Тогда подпрограмма импортируется всегда. Неважно, какой тег выбирает вызывающий код.

На самом деле каждый тег — это пакет. Он лежит внутри пакета `EXPORT` модуля. Вот пример: `Greeting::EXPORT::partings`. [Интроспекция модулей](/ru/advanced/module-introspection) показывает именно эти пакеты. С тегами большой модуль может держать группу по умолчанию маленькой. При этом программа всё равно может попросить больше возможностей.
