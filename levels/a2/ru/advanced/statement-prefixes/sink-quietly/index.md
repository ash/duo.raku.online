Есть ещё два префикса. Они выполняют код ради того, что он делает. Значение кода не важно.

Префикс `sink` выполняет код в _контексте sink_. Код выполняется только ради побочных эффектов. Raku выбрасывает результат. Это полезно с ленивой операцией. С `sink` вы заставляете её выполниться:

```raku
sink (1..3).map({ print "$_ " });
print "\n"; # 1 2 3
```

Здесь мы выполняем `map` только ради печати. `sink` следит, чтобы он правда выполнился. Потом `sink` выбрасывает список из `map`. Если ничто его не заставляет, ленивый `map` может вообще не выполниться. Так бывает, когда никто не использует его результат.

Префикс `quietly` выполняет блок и **скрывает его предупреждения**. Какой-то код обычно печатает предупреждение в поток ошибок. Внутри `quietly` такой код молчит:

```raku
my $value;
quietly {
    say $value + 1; # 1, без предупреждения "uninitialized value"
}
```

Обычно Raku показывает предупреждение, когда вы прибавляете `1` к неопределённому `$value`. Предупреждение говорит про «uninitialized value». Внутри `quietly` это предупреждение скрыто. Иногда вы знаете, что ваш код даёт предупреждение. Вам не нужен этот шум. Тогда используйте `quietly`. Но не используйте его часто. Предупреждение обычно показывает настоящую ошибку.
