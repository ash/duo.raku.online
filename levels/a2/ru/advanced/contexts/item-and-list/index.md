Есть ещё два контекста. Они решают одну вещь. Значение — это **список** из нескольких значений? Или это один **элемент**? Сигилы `@` и `$` показывают эту разницу.

В _контексте списка_ массив распадается на отдельные элементы. Цикл `for` ставит свой аргумент в контекст списка. Поэтому цикл проходит по каждому элементу:

```raku
my @a = 1, 2, 3;

my $count = 0;
$count++ for @a;
say $count; # 3
```

В _контексте элемента_ тот же массив — одно значение. Контекстуализатор `$( … )` задаёт контекст элемента. Теперь цикл видит только одну вещь. Поэтому он выполняется один раз:

```raku
my @a = 1, 2, 3;

my $count = 0;
$count++ for $(@a);
say $count; # 1
```

Контекст элемента объясняет и это. Вы присваиваете массив скаляру. Скаляр получает весь массив как один элемент. Он не копирует элементы. Причина в том, что `my $x = @a` ставит `@a` в контекст элемента. Обратите внимание: этот один элемент может быть другим контейнером. А в этом контейнере может быть много элементов:

```raku
my @a = 1, 2, 3;

my $var = @a;
say $var;      # [1 2 3]
say $var.WHAT; # (Array)
```

`$var` — это скалярный контейнер. Поэтому теперь он хранит один объект. Этот объект — `Array`. Это легко проверить. Используйте `$var` как своего рода ссылку на массив. Так это называют в других языках:

```raku
say $var[1]; # 2
```

Контекстуализатор `@( … )` делает обратное. Он задаёт контекст списка.

Есть ещё _контекст поглощения (sink context)_. В этом контексте никто не использует значение выражения. Raku просто выбрасывает это значение. Например, строка кода может быть нужна только ради побочного эффекта. Побочный эффект — это дополнительное действие кода, например печать. Иногда значение в контексте поглощения не делает ничего полезного. Тогда Raku может предупредить вас о «бесполезном использовании» (useless use). Это полезная подсказка. Наверное, вы забыли использовать результат.

Сигил, `$` или `@`, — это на самом деле выбор контекста. Иногда вам нужен другой контекст. Тогда контекстуализаторы `$( )` и `@( )` меняют его.
