`spurt` и `mkdir` создают что-то на диске. Две другие процедуры удаляют что-то с диска.

Процедура `unlink` удаляет файл:

```raku
spurt 'temp.txt', 'scratch data';
say 'temp.txt'.IO.e; # True

unlink 'temp.txt';
say 'temp.txt'.IO.e; # False
```

`unlink` удаляет файл с указанным именем. Как и другие процедуры для файловой системы, `unlink` — это ещё и метод. Вы вызываете его у объекта пути: `'temp.txt'.IO.unlink`.

Удаление происходит сразу, и это навсегда. Корзины нет. Файл нельзя вернуть. Заметьте ещё одну вещь. После удаления файла проверяйте его через `.e`. Этот метод проверяет, существует ли путь. Не используйте здесь `.f`. Методы `.f` и `.d` проверяют тип пути. Они выдают ошибку, когда пути нет.

Процедура `rmdir` удаляет каталог. Но каталог должен быть **пустым**:

```raku
mkdir 'reports';
rmdir 'reports';
say 'reports'.IO.e; # False
```

Если каталог не пустой, `rmdir` ничего не удаляет. Каталог остаётся на своём месте. Поэтому вы удаляете каталог с файлами в два шага. Сначала вы делаете его пустым. Потом вы удаляете его:

```raku
mkdir 'reports';
spurt 'reports/jan.txt', 'January';
spurt 'reports/feb.txt', 'February';

.unlink for 'reports'.IO.dir;   # удаляем все записи
rmdir 'reports';                # теперь каталог пуст
say 'reports'.IO.e;             # False
```

`'reports'.IO.dir` даёт список записей в каталоге. Вы видели это в предыдущей теме. Программа вызывает `.unlink` у каждой записи. Это удаляет их все. Теперь каталог пуст. Поэтому `rmdir` может его удалить. Этот простой цикл ожидает в каталоге только файлы. Но в каталоге могут быть и другие каталоги. Тогда сначала нужно очистить каждый внутренний каталог. Вы делаете это тем же способом.
