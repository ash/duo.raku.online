Вот один способ решить задачу.

## Код

```raku
class Negative is Exception {
    has $.n;

    method message {
        "$.n is negative";
    }
}

sub check($n) {
    Negative.new(n => $n).throw if $n < 0;
    return $n;
}

{
    say check(-5);

    CATCH {
        when Negative {
            say .message;
        }
    }
}

Negative.new(n => -10).throw;
```

🦋 Исходный код можно найти в файле [negative-error.raku](https://github.com/ash/raku-course/blob/master/exercises/oop/custom-exceptions/negative-error.raku).

## Вывод

```
-5 is negative
-10 is negative
  in block <unit> at negative-error.raku line 24
```

## Комментарии

1. `Negative is Exception` позволяет бросать этот класс. Его метод `message` строит текст из атрибута `n`.

1. `check` проверяет свои входные данные. Для отрицательного числа она бросает собственное исключение. Исключение выходит из `check`. Оно идёт к `CATCH` в блоке, который вызвал `check`. Там `when Negative` совпадает с ним по типу. Потом `CATCH` печатает сообщение. Это очень частое, реальное применение собственных исключений. Программа проверяет свои входные данные. Для плохого значения она бросает исключение своего типа.

1. Зачем вокруг вызова стоит `{ … }`? Фазер `CATCH` обрабатывает только исключения из **своего собственного блока**. Это блок, внутри которого стоит `CATCH`. Здесь в блоке вместе стоят вызов `check(-5)` и его `CATCH`. Вызов может дать сбой, и `CATCH` стоит здесь ради него. Поэтому исключение перехватывается прямо здесь. Потом программа идёт дальше сразу после блока. А если блока нет? Тогда `CATCH` работает для всей программы. Он перехватывает исключение. Но потом программа просто заканчивается. Программе негде продолжить работу.

1. Последняя строка, `Negative.new(n => -10).throw`, показывает обратный случай. Эта строка стоит **вне** блока. Поэтому исключение никто не перехватывает. Исключение поднимается до самого верха. Тогда программа умирает, то есть останавливается с ошибкой. Она печатает сообщение в стандартный поток ошибок. Ещё она печатает туда трассировку. Трассировка показывает, где в коде случилась ошибка. Потом программа завершается, и её код возврата не равен `0`. Так бывает с каждым исключением, которое вы не перехватили. И именно поэтому первому броску был нужен `CATCH`. Без него программа не может продолжить работу.
