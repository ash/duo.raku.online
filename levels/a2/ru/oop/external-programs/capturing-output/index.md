Обычно внешняя программа печатает на экран. Но, может быть, вы хотите прочитать её вывод в своей программе. Тогда добавьте `:out` при запуске программы. Вы получаете обратно объект `Proc`. У него есть дескриптор `.out`. Из этого дескриптора можно прочитать вывод:

```raku
my $proc = run 'echo', 'hello', :out;
my $output = $proc.out.slurp(:close);
say $output.chomp; # hello
```

`:out` отправляет стандартный вывод программы в `Proc`. Стандартный вывод — это поток для обычного вывода программы. Дескриптор `.out` работает как файловые дескрипторы из предыдущего раздела. `.slurp` читает из него весь текст сразу. Наречие `:close` — удобное сокращение. Оно закрывает дескриптор за вас после чтения. Раньше вы делали это сами с помощью `.close` у файлового дескриптора. Так ничего не остаётся открытым. Наконец, `.chomp` убирает перевод строки в конце. Этот перевод строки добавляет `echo`.

То же работает и с `shell`. Это полезно с конвейером. В конвейере одна команда передаёт свой вывод следующей. С `shell` можно перехватить конечный результат:

```raku
my $proc = shell 'echo hello | tr a-z A-Z', :out;
say $proc.out.slurp(:close).chomp; # HELLO
```

Можно перехватить и поток ошибок. Этот поток называется стандартным потоком ошибок. Туда программа печатает свои сообщения об ошибках. Для этого потока используйте `:err` и дескриптор `.err`. Можно передать и `:out`, и `:err`. Тогда два потока остаются раздельными. У каждого из них свой дескриптор. Поэтому каждый из них можно читать отдельно:

```raku
my $proc = run 'sh', '-c', 'echo out-line; echo err-line >&2', :out, :err;

say 'stdout: ', $proc.out.slurp(:close).chomp; # stdout: out-line
say 'stderr: ', $proc.err.slurp(:close).chomp; # stderr: err-line
```

Здесь команда оболочки печатает две строки. Одна строка идёт в стандартный вывод. Другая строка идёт в стандартный поток ошибок. Туда её отправляет часть `>&2`. Мы попросили оба потока. Поэтому `.out` и `.err` держат их отдельно. Обычный вывод программы никогда не смешивается с её сообщениями об ошибках.

Захват вывода очень полезен. Внешняя программа становится частью вашей программы. Вы запускаете её и читаете её результат. Потом ваша программа идёт дальше и использует эти данные.
