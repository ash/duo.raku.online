Исключение из `die` сразу всё останавливает. Иногда это слишком. Может быть, подпрограмма не может дать результат. Она должна сообщить об этой проблеме. Но вызывающий код должен решить, остановить ли программу. Вызывающий код — это код, который вызвал подпрограмму. Для такого случая в Raku есть _мягкие сбои_. Их создают с помощью `fail`.

Подпрограмма может вызвать `fail`. Тогда она не бросает исключение сразу. Вместо этого она возвращает вызывающему коду особый объект `Failure`. `Failure` — это значение с ошибкой внутри. Он не определён. Поэтому вызывающий код может тихо его проверить:

```raku
sub divide($a, $b) {
    fail 'cannot divide by zero' if $b == 0;
    return $a / $b;
}

say divide(10, 2);         # 5
say divide(10, 0).defined; # False
```

Первый вызов работает и возвращает `5`. Второй вызов даёт сбой. Он возвращает `Failure`. Для этого объекта `defined` даёт `False`. Поэтому вызывающий код может проверить результат, прежде чем его использовать.

Почему `Failure` называют _мягким_? Он становится настоящим брошенным исключением только в одном случае. Это когда вы используете его как значение без проверки. Но вы можете обработать его, например, проверить `defined`. Тогда он остаётся тихим. Так подпрограмма может сообщить о проблеме. Всей программе не нужно останавливаться.

## Вы это уже знаете

Такой сбой срабатывает не сразу, а позже. Так работает не только `fail`. Раньше в этой части вы два раза видели ту же идею.

**Деление на ноль** тихо создаёт значение. Оно бросает исключение, только когда вы на самом деле используете это значение:

```raku
my $x = 1 / 0;   # ошибки пока нет
say $x;           # бросает только здесь, когда значение используется
```

**Внешняя программа, которая дала сбой**, возвращает `Proc`. Он бросает исключение только в одном случае. Это когда вы выбрасываете `Proc` и не обрабатываете его. Сохраните `Proc` и посмотрите на него. Тогда он остаётся тихим значением:

```raku
run 'sh', '-c', 'exit 1';   # неудачный Proc отброшен, поэтому здесь бросается исключение
```

В каждом случае проблема не останавливает программу сразу. Она становится значением. Это значение можно проверить. Оно превращается в брошенное исключение только в двух случаях. Вы используете его без проверки или не обращаете на него внимания. Тема [Не всякая ошибка возникает сразу](/ru/oop/try/deferred-errors) показывает оба примера вместе.
