Иногда в программе на Raku что-то идёт не так. Например, нет файла, или код вызывает `die`. Тогда программа бросает ошибку. Такую ошибку называют _исключением_. Если никакой код не обрабатывает исключение, программа останавливается. Так происходит по умолчанию. Здесь помогает блок `try`. Это блок кода со словом `try` перед ним. Код в этом блоке может дать сбой. Но программа не падает.

Вы кладёте в блок `try` код, который может дать сбой. Может быть, код бросит исключение внутри блока. Тогда блок останавливается в этом месте. Но программа работает дальше:

```raku
my $result = try {
    die 'Boom!';
};

say "Still works";
```

`try` перехватывает `die`. Поэтому программа не падает. Она сразу переходит к следующей инструкции. Она печатает:

```
Still works
```

Здесь блок даёт сбой. Тогда он возвращает неопределённое значение. Поэтому `$result` не определён:

```raku
say $result.defined; # False
```

Raku хранит перехваченное исключение в специальной переменной `$!`. Оттуда можно прочитать сообщение исключения:

```raku
say $!.message; # Boom!
```

Итак, `try` помогает с фатальной ошибкой. Без `try` такая ошибка останавливает программу. С `try` ваша программа может посмотреть на ошибку. Потом она может на неё отреагировать. А если блок выполняется без исключения? Тогда в `$result` лежит значение блока. В этом случае `$!` не определён.
