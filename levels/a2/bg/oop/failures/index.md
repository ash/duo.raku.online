Изключение от `die` спира всичко веднага. Понякога това е твърде много. Може би подпрограмата не може да даде резултат. Тя трябва да съобщи за този проблем. Но извикващият трябва да реши дали програмата спира. Извикващият е кодът, който е извикал подпрограмата. За този случай Raku има _меки провали_. Създавате ги с `fail`.

Подпрограмата може да извика `fail`. Тогава тя не хвърля изключение веднага. Вместо това тя връща на извикващия специален обект `Failure`. `Failure` е стойност с грешка вътре. Той е недефиниран. Затова извикващият може тихо да провери за него:

```raku
sub divide($a, $b) {
    fail 'cannot divide by zero' if $b == 0;
    return $a / $b;
}

say divide(10, 2);         # 5
say divide(10, 0).defined; # False
```

Първото извикване работи и връща `5`. Второто извикване се проваля. То връща `Failure`. За този обект `defined` дава `False`. Затова извикващият може да провери резултата, преди да го използва.

Защо `Failure` се нарича _мек_? Той става истинско, хвърлено изключение само в един случай. Това е, когато го използвате като стойност без проверка. Но можете да го обработите, например с проверка за `defined`. Тогава той остава тих. Така подпрограмата може да съобщи за проблем. Не е нужно цялата програма да спира.

## Вече познавате това

Този вид провал се отлага за по-късно. Не само `fail` работи по този начин. По-рано в тази част видяхте същата идея два пъти.

**Делението на нула** тихо създава стойност. То хвърля изключение едва когато наистина използвате стойността:

```raku
my $x = 1 / 0;   # още няма грешка
say $x;           # хвърля едва тук, когато стойността се използва
```

**Провалила се външна програма** връща `Proc`. Той хвърля изключение само в един случай. Това е, когато изхвърлите `Proc`, без да го обработите. Запазете `Proc` и го разгледайте. Тогава той остава тиха стойност:

```raku
run 'sh', '-c', 'exit 1';   # провалилият се Proc е изхвърлен, затова това хвърля
```

И в двата случая проблемът не спира програмата веднага. Той става стойност. Можете да проверите тази стойност. Тя става хвърлено изключение само в два случая. Използвате я без проверка или не ѝ обръщате внимание. Темата [Не всяка грешка е незабавна](/bg/oop/try/deferred-errors) показва двата примера заедно.
