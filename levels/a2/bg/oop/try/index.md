Понякога нещо се обърква в програма на Raku. Например липсва файл или кодът извиква `die`. Тогава програмата хвърля грешка. Такъв вид грешка се нарича _изключение_. Ако никакъв код не обработи изключението, програмата спира. Така е по подразбиране. Тук помага блокът `try`. Това е блок код с думата `try` пред него. Кодът в този блок може да се провали. Но програмата не се срива.

Слагате кода, който може да се провали, в блок `try`. Може би кодът хвърля изключение вътре в блока. Тогава блокът спира на това място. Но програмата продължава:

```raku
my $result = try {
    die 'Boom!';
};

say "Still works";
```

`try` прихваща `die`. Затова програмата не се срива. Тя продължава направо със следващия оператор. Програмата отпечатва:

```
Still works
```

Тук блокът се проваля. Тогава той дава недефинирана стойност. Затова `$result` е недефинирана:

```raku
say $result.defined; # False
```

Raku пази прихванатото изключение в специалната променлива `$!`. Оттам можете да прочетете съобщението на изключението:

```raku
say $!.message; # Boom!
```

Така `try` помага при фатална грешка. Без `try` такава грешка спира програмата. С `try` програмата ви може да разгледа грешката. После тя може да реагира на нея. Какво става, ако блокът се изпълни без изключение? Тогава `$result` съдържа стойността на блока. В този случай `$!` е недефинирана.
