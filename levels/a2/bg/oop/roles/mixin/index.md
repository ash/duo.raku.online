Не е нужно да вграждате ролята в клас. Можете да дадете роля и на обект, който вече съществува. За това използвайте оператора `but`. Той вмесва ролята в един-единствен обект. Това става, докато програмата работи. После `but` връща нов обект с ролята:

```raku
role Loud {
    method greet {
        callsame().uc;
    }
}

class Greeter {
    method greet {
        'Hello';
    }
}

my $quiet = Greeter.new;
my $loud  = Greeter.new but Loud;

say $quiet.greet; # Hello
say $loud.greet;  # HELLO
```

Само `$loud` получи ролята. Класът `Greeter` и всички други обекти `Greeter` остават същите. Затова `$quiet` още поздравява по обичайния начин. Понякога ролята и класът имат методи с едно и също име. Тогава версията от ролята печели. А `callsame` извиква другия метод, който ролята предефинира. Тук това е първоначалният `greet` от `Greeter`. После неговият резултат се променя на главни букви.

Обектът може да получи роля по този начин. Тогава се смята, че той изпълнява тази роля:

```raku
say $quiet ~~ Loud; # False
say $loud  ~~ Loud; # True
```

`but` не променя първоначалния обект. Той ви дава нов обект. Може би искате да промените самия обект. Тогава използвайте вместо това оператора `does`:

```raku
my $speaker = Greeter.new;
$speaker does Loud;
say $speaker.greet; # HELLO
```

Можете да вмесвате роли в отделни обекти. Така решавате за всеки обект какво допълнително поведение получава. Не ви трябва отделен клас за всяка комбинация.
