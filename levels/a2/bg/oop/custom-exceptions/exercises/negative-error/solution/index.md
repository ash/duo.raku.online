Ето един начин да решите задачата.

## Код

```raku
class Negative is Exception {
    has $.n;

    method message {
        "$.n is negative";
    }
}

sub check($n) {
    Negative.new(n => $n).throw if $n < 0;
    return $n;
}

{
    say check(-5);

    CATCH {
        when Negative {
            say .message;
        }
    }
}

Negative.new(n => -10).throw;
```

🦋 Намерете програмата във файла [negative-error.raku](https://github.com/ash/raku-course/blob/master/exercises/oop/custom-exceptions/negative-error.raku).

## Коментари

1. `Negative is Exception` ви позволява да хвърляте този клас. Неговият метод `message` съставя текста от атрибута `n`.

1. `check` проверява входа си. За отрицателно число тя хвърля собственото изключение. Изключението излиза от `check`. То отива до `CATCH` в блока, който е извикал `check`. Там `when Negative` го съпоставя по неговия тип. После `CATCH` отпечатва съобщението. Това е много честа, реална употреба на собствените изключения. Програмата проверява входа си. За лоша стойност тя хвърля изключение от свой собствен тип.

1. Защо около извикването има `{ … }`? Фазерът `CATCH` обработва само изключенията от **своя собствен блок**. Това е блокът, в който е `CATCH`. Тук блокът държи извикването `check(-5)` заедно с неговия `CATCH`. Извикването може да се провали, а `CATCH` е там за този случай. Затова изключението се прихваща точно тук. После програмата продължава веднага след блока. Ами ако няма блок? Тогава `CATCH` работи за цялата програма. Той прихваща изключението. Но после програмата просто свършва. Няма добро място, откъдето да продължи.

1. Последният ред, `Negative.new(n => -10).throw`, показва обратния случай. Този ред е **извън** блока. Затова нищо не прихваща изключението. Изключението стига чак до върха. Тогава програмата умира, тоест спира с грешка. Тя отпечатва съобщението в стандартната грешка. Там тя отпечатва и обратна следа. Обратната следа показва къде в кода е станала грешката. После програмата завършва с код на изход, различен от `0`. Това става с всяко изключение, което не прихванете. И затова първото хвърляне имаше нужда от `CATCH`. Без него програмата не може да продължи.
