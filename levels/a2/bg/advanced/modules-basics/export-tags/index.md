Маркирайте подпрограма с `is export`. Тогава тя отива в групата _по подразбиране_ за експортиране на модула. Обикновен `use` внася имената от тази група. Можете също да дадете на `is export` _таг_. С таговете разпределяте експортите в групи с имена. Тогава всяка програма взема групата, която иска.

Пишете тага в скоби след `is export`:

```raku
unit module Greeting;

sub hello($name)   is export            { "Hello, $name!" }
sub goodbye($name) is export(:partings) { "Goodbye, $name!" }
```

`hello` няма таг. Затова е в групата по подразбиране. `goodbye` има тага `:partings`.

Обикновен `use` импортира само групата по подразбиране:

```raku
use Greeting;      # hello is available; goodbye is not
```

Сега посочете таг. Тогава `use` импортира тази група вместо това. Това може да ви изненада. Той _не_ импортира и групата по подразбиране:

```raku
use Greeting :partings; # goodbye is available; hello is not
```

С `:partings` получавате точно тази група. Искате ли всички експорти на модула? Тогава използвайте вградения таг `:ALL`:

```raku
use Greeting :ALL; # both hello and goodbye
```

Добре е да знаете два специални тага. Всеки модул поддържа `:ALL`. Той импортира всички експорти на модула. Можете да сложите `:MANDATORY` на рутина. Тогава рутината винаги се импортира. Няма значение кой таг избира извикващият код.

Всъщност всеки таг е пакет. Той е вътре в пакета `EXPORT` на модула. Пример за това е `Greeting::EXPORT::partings`. [Интроспекцията на модулите](/bg/advanced/module-introspection) показва точно тези пакети. С таговете голям модул може да държи групата си по подразбиране малка. Програмата пак може да поиска още функции.
