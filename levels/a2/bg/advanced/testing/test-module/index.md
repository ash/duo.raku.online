За да получите инструментите за тестване, напишете `use Test`. Най-простата проверка е `ok`. Тя минава, когато условието ѝ е вярно. Всяка проверка може да има и описание:

```raku
use Test;

ok 1 == 1, 'one equals one';
ok 2 > 1,  'two is greater';

done-testing;
```

Изпълнете тази програма. Тя отпечатва резултата в стандартния формат за тестове. Този формат се казва _TAP_:

```
ok 1 - one equals one
ok 2 - two is greater
1..2
```

За всяка проверка, която минава, виждате `ok` с нейния номер и описание. Проверка, която не минава, показва `not ok`. Последният ред, `1..2`, е _планът_. Той казва колко теста са се изпълнили. Извикването на `done-testing` в края отпечатва този план автоматично.

Понякога очаквате определена стойност. Тогава `is` е по-ясно от `ok`. Ако тестът не мине, `is` показва две стойности. Показва стойността, която очаквате, и стойността, която получавате:

```raku
use Test;

is 2 + 2, 4, 'addition works';

done-testing;
```

Това отпечатва `ok 1 - addition works`. Сега да видим как `is` съобщава за неуспех. Дайте на `is` грешна очаквана стойност:

```raku
use Test;

is 2 + 2, 5, 'addition works';

done-testing;
```

Сега проверката не минава. Изходът показва точно какво не е наред:

```
not ok 1 - addition works
# Failed test 'addition works'
# at test.raku line 3
# expected: '5'
#      got: '4'
1..1
# You failed 1 test of 1
```

Редът `not ok` показва неуспеха. Под него още редове обясняват проблема. Те показват стойността, която очаквате, и стойността, която получавате. Затова, когато ви трябва определена стойност, `is` помага повече от самото `ok`.

С `ok`, `is` и `done-testing` вече можете да напишете полезен тестов файл. Следващата тема показва [другите сравнения](/bg/advanced/testing/comparisons).
