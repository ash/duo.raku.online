Ето едно възможно решение.

## Код

```raku
use Test;

plan 2;

my @sorted = (3, 1, 2).sort;
is-deeply @sorted, [1, 2, 3], 'sorted';

is 10 % 3, 1, 'remainder';
```

🦋 Можете да намерите пълния код във файла [test-a-list.raku](https://github.com/ash/raku-course/blob/master/exercises/advanced/testing/test-a-list.raku).

## Резултат

```
1..2
ok 1 - sorted
ok 2 - remainder
```

## Коментари

1. `plan 2` дава броя, преди да започнат тестовете, затова редът `1..2` идва пръв. Ако след това файлът изпълни различен брой проверки, наборът от тестове ще се провали. `done-testing` не може да ви даде тази защита.

1. `is-deeply` проверява дали двата списъка са точно равни, включително типовете им. Сортирането на `3, 1, 2` дава `1, 2, 3`, което съвпада.

1. `is` проверява дали две стойности са просто равни. Ако тестът не мине, показва и двете стойности. Тук `10 % 3` е `1`, което е очакваната стойност. Затова и вторият тест минава.
