Зареждате инструментите за тестване с `use Test`. Най-основната проверка е `ok`, която минава, когато условието ѝ е вярно. Всяка проверка може да приеме и описание:

```raku
use Test;

ok 1 == 1, 'one equals one';
ok 2 > 1,  'two is greater';

done-testing;
```

Когато я изпълните, тя извежда това в стандартния тестов формат, наречен _TAP_:

```
ok 1 - one equals one
ok 2 - two is greater
1..2
```

Всяка проверка, която минава, се показва като `ok` с нейния номер и описание. Неуспешна проверка би показала `not ok`. Последният ред, `1..2`, е _планът_, който казва колко теста са се изпълнили. Извикването на `done-testing` в края извежда този план автоматично.

Когато очаквате определена стойност, `is` е по-ясно от `ok`. Ако тестът не мине, `is` показва и очакваната, и действителната стойност:

```raku
use Test;

is 2 + 2, 4, 'addition works';

done-testing;
```

Това извежда `ok 1 - addition works`. За да видите как `is` съобщава за проблем, дайте му грешна очаквана стойност:

```raku
use Test;

is 2 + 2, 5, 'addition works';

done-testing;
```

Сега проверката се проваля и изходът обяснява точно какво се е объркало:

```
not ok 1 - addition works
# Failed test 'addition works'
# at test.raku line 3
# expected: '5'
#      got: '4'
1..1
# You failed 1 test of 1
```

Редът `not ok` отбелязва неуспеха. Редовете под него показват какво се е очаквало и какво програмата всъщност е получила. Затова, когато определена стойност е важна, `is` е по-полезно от обикновено `ok`.

`ok`, `is` и `done-testing` вече стигат за полезен тестов файл. Следващата тема добавя [другите сравнения](/bg/advanced/testing/comparisons).
