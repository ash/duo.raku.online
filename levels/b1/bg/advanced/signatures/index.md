В частта „Основи“ вие [дефинирахте подпрограми с позиционни и именувани параметри](/bg/essentials/functions). Също така задавахте на параметрите стойности по подразбиране. Списъкът от параметри се нарича _сигнатура_. Този раздел показва още две неща, които сигнатурата може да прави. Тя може да направи параметър незадължителен и може да събира всякакъв брой допълнителни аргументи.

## Незадължителни параметри

Параметър с въпросителен знак след него е _незадължителен_. Това означава, че извикващият може да го пропусне. В този случай параметърът е недефиниран. Затова можете да му дадете резервна стойност с оператора defined-or `//`:

```raku
sub greet($name, $greeting?) {
    my $g = $greeting // 'Hello';
    say "$g, $name!";
}

greet('Anna');           # Hello, Anna!
greet('Anna', 'Hi');     # Hi, Anna!
```

Когато `greet` е извикана с един аргумент, `$greeting` е недефинирана. Затова `//` използва `'Hello'` вместо нея.

## Slurpy параметри

Параметър, отбелязан със `*`, е _slurpy_. Той взема всички останали аргументи. Slurpy масив, записан като `*@`, събира всякакъв брой позиционни аргументи в масив:

```raku
sub count-them(*@items) {
    say @items.elems;
}

count-them(1, 2, 3, 4); # 4
count-them('a', 'b');   # 2
```

Можете да смесвате обикновени параметри със slurpy параметър. Фиксираните параметри получават стойностите си първи. Каквото остане, отива в slurpy масива:

```raku
sub titles($name, *@titles) {
    say "$name has {@titles.elems} title(s)";
}

titles('Anna', 'Dr', 'Prof'); # Anna has 2 title(s)
```

Slurpy хешът работи по същия начин. Записва се като `*%` и събира всички допълнителни именувани аргументи в хеш:

```raku
sub register($name, *%options) {
    say "$name: {%options.elems} option(s)";
    say "role is %options<role>";
}

register('Anna', role => 'admin', active => True);
```

Двата именувани аргумента стават ключове в `%options`, затова програмата отпечатва:

```
Anna: 2 option(s)
role is admin
```
