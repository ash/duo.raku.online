Когато маркирате подпрограма с `is export`, тя попада в групата _по подразбиране_ за експортиране на модула. Това са имената, които обикновен `use` внася. Можете също да дадете на `is export` _таг_. Таговете разпределят експортите в именувани групи. Тогава всяка програма може да избере групата, която иска.

Тагът се записва в скоби след `is export`:

```raku
unit module Greeting;

sub hello($name)   is export            { "Hello, $name!" }
sub goodbye($name) is export(:partings) { "Goodbye, $name!" }
```

`hello` няма таг, така че принадлежи към групата по подразбиране. `goodbye` има тага `:partings`.

Обикновен `use` импортира само групата по подразбиране:

```raku
use Greeting;      # hello is available; goodbye is not
```

Ако посочите таг, `use` импортира тази група вместо това. Може би изненадващо, той _не_ импортира и групата по подразбиране:

```raku
use Greeting :partings; # goodbye is available; hello is not
```

Когато поискате `:partings`, получавате точно тази група. За да импортирате всичко, което модулът експортира, използвайте вградения таг `:ALL`:

```raku
use Greeting :ALL; # both hello and goodbye
```

Има два специални тага, които е полезно да знаете. Всеки модул поддържа `:ALL`, който импортира всички негови експорти. Можете да сложите `:MANDATORY` на рутина, която трябва винаги да се импортира. Няма значение кой таг избира извикващият код.

Всеки таг всъщност е пакет вътре в пакета `EXPORT` на модула, например `Greeting::EXPORT::partings`. Точно това показва [интроспекцията на модулите](/bg/advanced/module-introspection). С таговете по-голям модул може да държи малък набора си от експорти по подразбиране. Той пак може да предлага допълнителни функции, когато програмата ги поиска.
