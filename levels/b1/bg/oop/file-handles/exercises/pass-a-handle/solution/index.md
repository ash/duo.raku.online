Ето едно възможно решение.

## Код

```raku
sub log-line($fh, $message) {
    $fh.say($message);
}

my $fh = open 'log.txt', :w;
log-line($fh, 'started');
log-line($fh, 'working');
log-line($fh, 'done');
$fh.close;

print slurp 'log.txt';
```

🦋 Намерете програмата във файла [pass-a-handle.raku](https://github.com/ash/raku-course/blob/master/exercises/oop/file-handles/pass-a-handle.raku).

## Изход

```
started
working
done
```

## Коментари

1. Манипулаторът, който `open` връща, е просто стойност, пазена в `$fh`. Затова той може да бъде аргумент на `log-line`, като всеки низ или число. Вътре в подпрограмата `$fh.say` пише чрез същия отворен манипулатор.

1. Манипулаторът остава отворен през трите извиквания. Затова всяко `log-line` добавя още един ред в края на същия файл. След това `close` запазва всичко на диска, а `slurp` прочита трите реда обратно.

1. Точно това прави манипулаторите лесни за съчетаване. Функцията може да приеме манипулатор и да пише в него или да чете от него. Не я интересува към кой файл сочи манипулаторът. Кодът, който извиква функцията, решава това, когато отваря файла.
