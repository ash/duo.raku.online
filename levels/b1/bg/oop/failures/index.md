Хвърлянето на изключение с `die` спира всичко веднага. Понякога това е твърде рязко. Може да искате подпрограмата да съобщи, че не е могла да даде резултат. Но извикващият трябва да реши дали това е фатално. За целта Raku има _меки провали_, които създавате с `fail`.

Когато подпрограма извика `fail`, тя не хвърля изключение веднага. Вместо това тя връща на извикващия специален обект `Failure`. `Failure` е недефиниран, така че извикващият може тихо да провери за него:

```raku
sub divide($a, $b) {
    fail 'cannot divide by zero' if $b == 0;
    return $a / $b;
}

say divide(10, 2);         # 5
say divide(10, 0).defined; # False
```

Успешното извикване връща `5`. Провалилото се извикване връща `Failure`, а `defined` дава `False` за него. Затова извикващият може да провери резултата, преди да го използва.

Защо `Failure` се нарича _мек_? Той става истинско, хвърлено изключение само в един случай. Това става, когато го използвате като стойност, без първо да го проверите. Докато го обработвате, например като проверявате `defined`, той остава тих. Така подпрограмата може да съобщи за проблем, без да спира цялата програма.

## Виждали сте това и преди

Този отложен вид провал не идва само от `fail`. По-рано в тази част срещнахте същата идея два пъти.

**Делението на нула** тихо създава стойност. То хвърля изключение само когато наистина използвате тази стойност:

```raku
my $x = 1 / 0;   # още няма грешка
say $x;           # хвърля едва тук, когато стойността се използва
```

**Провалила се външна програма** връща `Proc`. Той хвърля изключение само ако го изхвърлите, без да го обработите. Ако го запазите и го разгледате, той остава тиха стойност:

```raku
run 'sh', '-c', 'exit 1';   # провалилият се Proc е изхвърлен, затова това хвърля
```

И в двата случая проблемът не спира програмата в момента, в който се случи. Вместо това той става стойност, която можете да проверите. Тя става хвърлено изключение само когато я използвате без проверка или не ѝ обърнете внимание. Темата [Не всяка грешка е незабавна](/bg/oop/try/deferred-errors) показва тези два примера един до друг.
