Ето едно възможно решение.

## Код

```raku
class Negative is Exception {
    has $.n;

    method message {
        "$.n is negative";
    }
}

sub check($n) {
    Negative.new(n => $n).throw if $n < 0;
    return $n;
}

{
    say check(-5);

    CATCH {
        when Negative {
            say .message;
        }
    }
}

Negative.new(n => -10).throw;
```

🦋 Намерете програмата във файла [negative-error.raku](https://github.com/ash/raku-course/blob/master/exercises/oop/custom-exceptions/negative-error.raku).

## Коментари

1. `Negative is Exception` дава възможност да хвърляте класа. Методът му `message` съставя текста от атрибута `n`.

1. `check` проверява входа си и хвърля собственото изключение за отрицателно число. Изключението излиза от `check` и стига до `CATCH` в извикващия блок. Там `when Negative` го съпоставя по типа му и отпечатва съобщението. Това е много честа, реална употреба на собствените изключения. Кодът проверява входа си и съобщава за лоши стойности с изключение от свой собствен тип.

1. Защо около извикването има `{ … }`? Фазерът `CATCH` обработва само изключенията, хвърлени в **блока, който го съдържа**. Блокът събира рискованото `check(-5)` заедно с `CATCH`, който го пази. Затова изключението се прихваща точно тук, а програмата продължава веднага след блока. Без блока `CATCH` би пазил вместо това цялата програма. Той би прихванал изключението, но после програмата просто би свършила. Нямаше да има естествено място, откъдето да продължи.

1. Последното `Negative.new(n => -10).throw` показва другата страна на това. То е **извън** блока, така че нищо не го прихваща. Изключението стига чак до върха и програмата умира. Тя отпечатва съобщението и обратната следа в стандартната грешка. После тя завършва с ненулев код на изход. Това става с всяко изключение, което не прихванете. И точно затова първото хвърляне имаше нужда от `CATCH`, за да оцелее.
