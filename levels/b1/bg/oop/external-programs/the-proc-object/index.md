Всяко извикване на `run` или `shell` връща обект `Proc`. Това е малък запис, който описва коя програма е работила и как е приключила. Предишните теми използваха манипулатора му `.out`, за да четат изхода. Но `Proc` съдържа повече от това.

Най-полезната част е **кодът на изход**. С малко цяло число програмата казва на онзи, който я е стартирал, дали е успяла. `0` означава успех. Всяко друго число е код за провал, който програмата избира сама. `.exitcode` ви дава това число:

```raku
my $proc = run 'sh', '-c', 'exit 3';
say $proc.exitcode; # 3
```

Обикновено питате само въпрос с отговор „да“ или „не“: проработи ли? За това `Proc` е просто истина, когато кодът на изход е `0`. Иначе той е лъжа. Затова можете да го проверите направо:

```raku
my $proc = run 'ls', '/', :out;
$proc.out.slurp(:close);
say $proc ?? 'ok' !! 'failed'; # ok
```

`Proc` помни и коя команда е стартирал, в `.command`:

```raku
my $proc = run 'echo', 'hi', :out;
$proc.out.slurp(:close);
say $proc.command; # (echo hi)
```

Има едно нещо, за което да внимавате. Ако команда се провали и вие просто **пренебрегнете** върнатия `Proc`, Raku повдига изключение. Той не оставя провала да мине незабелязано:

```raku
run 'sh', '-c', 'exit 1';
# умира: The spawned command 'sh' exited unsuccessfully (exit code: 1, signal: 0)
```

Ненулевият код на изход обикновено означава, че нещо се е объркало. Затова, ако изхвърлите провалил се `Proc`, той хвърля изключение. Това става, когато той излезе от обхват. Причината е *изхвърлянето* на резултата, а не пренебрегването на кода на изход. Простото запазване на `Proc` в променлива е достатъчно, за да избегнете изключението. Дори не е нужно да го поглеждате отново.

```raku
my $proc = run 'sh', '-c', 'exit 1'; # няма грешка, макар да се провали
# …и $proc никога повече не се използва
```

Затова, ако *очаквате*, че команда може да се провали, запазете нейния `Proc`. После погледнете `.exitcode` или го проверете като булева стойност. Правете това винаги, когато искате да разберете какво се е случило.
