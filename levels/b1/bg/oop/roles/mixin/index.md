Ролята не е задължително да е вградена в клас. Можете да я дадете и на обект, който вече съществува, с оператора `but`. Той вмесва ролята в един-единствен обект по време на изпълнение. После връща нов обект, който има ролята:

```raku
role Loud {
    method greet {
        callsame().uc;
    }
}

class Greeter {
    method greet {
        'Hello';
    }
}

my $quiet = Greeter.new;
my $loud  = Greeter.new but Loud;

say $quiet.greet; # Hello
say $loud.greet;  # HELLO
```

Само `$loud` получи ролята. Класът `Greeter` и всички други обекти `Greeter` остават същите. Затова `$quiet` все още поздравява по обичайния начин. Понякога и ролята, и класът дефинират метод с едно и също име. В такъв случай версията на ролята надделява. А `callsame` извиква метода, който тя е предефинирала. Тук това е първоначалният `greet` от `Greeter`. След това резултатът му се превръща в главни букви.

За обект с вмесена роля се смята, че изпълнява тази роля:

```raku
say $quiet ~~ Loud; # False
say $loud  ~~ Loud; # True
```

`but` оставя първоначалния обект какъвто си е бил и ви дава нов. Ако искате да промените самия съществуващ обект, използвайте вместо това оператора `does`:

```raku
my $speaker = Greeter.new;
$speaker does Loud;
say $speaker.greet; # HELLO
```

Когато вмесвате роли в отделни обекти, вие решавате какво допълнително поведение получава всеки обект. Не е нужно да дефинирате отделен клас за всяка комбинация.
