Когда в программе на Raku что-то идёт не так, бросается _исключение_. Так бывает, например, когда нет файла или когда вы сами вызываете `die`. По умолчанию исключение, которое никто не обработал, останавливает программу. Блок `try` позволяет выполнить код, который может дать сбой, без падения программы.

Вы помещаете рискованный код в блок `try`. Если внутри него бросается исключение, блок на этом месте останавливается. Но программа продолжает работу:

```raku
my $result = try {
    die 'Boom!';
};

say "Still works";
```

`try` перехватывает `die`, поэтому программа не падает. Она сразу переходит к следующей инструкции и печатает:

```
Still works
```

Когда блок вот так даёт сбой, он возвращает неопределённое значение. Поэтому `$result` не определён:

```raku
say $result.defined; # False
```

Перехваченное исключение хранится в специальной переменной `$!`. Оттуда можно прочитать его сообщение:

```raku
say $!.message; # Boom!
```

Итак, `try` превращает фатальную ошибку в то, что ваша программа может проверить и на что может отреагировать. Если блок выполнился без исключений, в `$result` хранится его значение, а `$!` не определён.
