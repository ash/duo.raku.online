Роль не обязательно должна быть встроена в класс. Её можно дать и уже существующему объекту с помощью оператора `but`. Он подмешивает роль в один-единственный объект во время работы программы. Потом он возвращает новый объект, у которого есть эта роль:

```raku
role Loud {
    method greet {
        callsame().uc;
    }
}

class Greeter {
    method greet {
        'Hello';
    }
}

my $quiet = Greeter.new;
my $loud  = Greeter.new but Loud;

say $quiet.greet; # Hello
say $loud.greet;  # HELLO
```

Роль получил только `$loud`. Класс `Greeter` и все остальные объекты `Greeter` остаются прежними. Поэтому `$quiet` по-прежнему здоровается обычным образом. Иногда и роль, и класс определяют метод с одним и тем же именем. В этом случае побеждает версия из роли. А `callsame` вызывает тот метод, который она переопределила. Здесь это исходный `greet` из `Greeter`. Затем его результат переводится в верхний регистр.

Если в объект подмешана роль, считается, что он её выполняет:

```raku
say $quiet ~~ Loud; # False
say $loud  ~~ Loud; # True
```

`but` оставляет исходный объект как был и даёт вам новый. Если вы хотите изменить сам существующий объект, используйте вместо этого оператор `does`:

```raku
my $speaker = Greeter.new;
$speaker does Loud;
say $speaker.greet; # HELLO
```

Когда вы подмешиваете роли в отдельные объекты, вы решаете, какое дополнительное поведение получит каждый объект. Вам не нужно определять отдельный класс для каждого сочетания.
