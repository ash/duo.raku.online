Если бросить исключение через `die`, всё сразу останавливается. Иногда это слишком резко. Может быть, вы хотите, чтобы подпрограмма сообщила, что не смогла дать результат. Но решать, фатально ли это, должна вызывающая сторона. Для этого в Raku есть _мягкие сбои_, которые создаются с помощью `fail`.

Когда подпрограмма вызывает `fail`, она не бросает исключение сразу. Вместо этого она возвращает вызывающей стороне особый объект `Failure`. `Failure` не определён, поэтому вызывающий код может тихо его проверить:

```raku
sub divide($a, $b) {
    fail 'cannot divide by zero' if $b == 0;
    return $a / $b;
}

say divide(10, 2);         # 5
say divide(10, 0).defined; # False
```

Успешный вызов возвращает `5`. Неудачный вызов возвращает `Failure`, и `defined` даёт для него `False`. Поэтому вызывающая сторона может проверить результат, прежде чем его использовать.

Почему `Failure` называют _мягким_? Он становится настоящим брошенным исключением только в одном случае. Это происходит, когда вы используете его как значение, не проверив его сначала. Пока вы его обрабатываете, например проверяете `defined`, он остаётся тихим. Поэтому подпрограмма может сообщить о проблеме и не останавливать всю программу.

## Вы это уже видели

Такой отложенный сбой бывает не только у `fail`. Раньше в этой части вы уже дважды встречали ту же идею.

**Деление на ноль** тихо даёт значение. Оно бросает исключение, только когда вы действительно используете это значение:

```raku
my $x = 1 / 0;   # ошибки пока нет
say $x;           # бросает только здесь, когда значение используется
```

**Внешняя программа, которая дала сбой**, возвращает `Proc`. Он бросает исключение, только если вы выбросите его, не обработав. Если вы сохраните его и посмотрите на него, он останется тихим значением:

```raku
run 'sh', '-c', 'exit 1';   # неудачный Proc отброшен, поэтому здесь бросается исключение
```

В каждом случае проблема не останавливает программу в тот момент, когда она возникает. Вместо этого она становится значением, которое можно проверить. Оно становится брошенным исключением, только если вы используете его без проверки или не обращаете на него внимания. Тема [Не всякая ошибка возникает сразу](/ru/oop/try/deferred-errors) показывает эти два примера рядом.
