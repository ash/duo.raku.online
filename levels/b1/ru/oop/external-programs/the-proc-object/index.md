Каждый вызов `run` или `shell` возвращает объект `Proc`. Это небольшая запись, которая описывает, какая программа выполнялась и как она завершилась. В прошлых темах мы читали вывод через его дескриптор `.out`. Но в `Proc` есть и кое-что ещё.

Самая полезная часть — **код возврата**. Небольшим целым числом программа сообщает тому, кто её запустил, удалась ли она. `0` означает успех. Любое другое число — это код неудачи, который программа выбирает сама. `.exitcode` даёт вам это число:

```raku
my $proc = run 'sh', '-c', 'exit 3';
say $proc.exitcode; # 3
```

Обычно вы задаёте только вопрос «да или нет»: всё сработало? Для этого `Proc` просто истинен, когда код возврата равен `0`. Иначе он ложен. Поэтому его можно проверять напрямую:

```raku
my $proc = run 'ls', '/', :out;
$proc.out.slurp(:close);
say $proc ?? 'ok' !! 'failed'; # ok
```

`Proc` также помнит, какую команду он запустил, — в `.command`:

```raku
my $proc = run 'echo', 'hi', :out;
$proc.out.slurp(:close);
say $proc.command; # (echo hi)
```

За одним нужно следить. Если команда дала сбой, а вы просто **проигнорируете** возвращённый `Proc`, Raku бросит исключение. Он не даёт сбою пройти незамеченным:

```raku
run 'sh', '-c', 'exit 1';
# умирает: The spawned command 'sh' exited unsuccessfully (exit code: 1, signal: 0)
```

Ненулевой код возврата обычно значит, что что-то пошло не так. Поэтому если вы выбросите неудачный `Proc`, он бросит исключение. Это происходит, когда он выходит из области видимости. Причина — именно то, что вы *выбрасываете* результат, а не то, что вы не проверяете код возврата. Чтобы не было исключения, достаточно просто сохранить `Proc` в переменной. Вам даже не нужно смотреть на неё снова.

```raku
my $proc = run 'sh', '-c', 'exit 1'; # ошибки нет, хотя команда и не удалась
# …и $proc больше нигде не используется
```

Поэтому если вы *ожидаете*, что команда может не сработать, сохраните её `Proc`. Затем смотрите на `.exitcode` или проверяйте его как булево значение. Делайте так всякий раз, когда хотите узнать, что произошло.
