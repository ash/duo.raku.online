Иногда вашей программе нужно прочитать то, что печатает внешняя программа, а не показывать это на экране. Для этого передайте `:out`, когда запускаете программу. Тогда у возвращённого `Proc` есть дескриптор `.out`, из которого можно читать:

```raku
my $proc = run 'echo', 'hello', :out;
my $output = $proc.out.slurp(:close);
say $output.chomp; # hello
```

`:out` отправляет стандартный вывод программы в `Proc`. Дескриптор `.out` работает как файловые дескрипторы из предыдущего раздела. `.slurp` читает из него всё сразу. Наречие `:close` — удобное сокращение: после чтения оно закрывает дескриптор за вас. Ту же уборку вы делали сами с помощью `.close` у файлового дескриптора. Так ничего не остаётся открытым. Наконец, `.chomp` убирает перевод строки, который `echo` добавляет в конце.

То же работает и с `shell`. Это удобно, когда нужно перехватить результат конвейера:

```raku
my $proc = shell 'echo hello | tr a-z A-Z', :out;
say $proc.out.slurp(:close).chomp; # HELLO
```

Перехватить можно и поток ошибок — с помощью `:err` и соответствующего дескриптора `.err`. Если передать и `:out`, и `:err`, два потока останутся раздельными. У каждого из них свой дескриптор, поэтому их можно читать по отдельности:

```raku
my $proc = run 'sh', '-c', 'echo out-line; echo err-line >&2', :out, :err;

say 'stdout: ', $proc.out.slurp(:close).chomp; # stdout: out-line
say 'stderr: ', $proc.err.slurp(:close).chomp; # stderr: err-line
```

Здесь команда оболочки печатает одну строку в стандартный вывод, а другую — в стандартный поток ошибок. Часть `>&2` перенаправляет туда вторую строку. Мы попросили оба потока, поэтому `.out` и `.err` хранят их отдельно. Обычный вывод программы никогда не смешивается с её сообщениями об ошибках.

Захват вывода позволяет использовать внешнюю программу как строительный блок. Вы запускаете её, читаете результат и дальше работаете с этими данными в своей программе.
