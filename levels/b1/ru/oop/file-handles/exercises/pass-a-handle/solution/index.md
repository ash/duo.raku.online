Вот одно возможное решение.

## Код

```raku
sub log-line($fh, $message) {
    $fh.say($message);
}

my $fh = open 'log.txt', :w;
log-line($fh, 'started');
log-line($fh, 'working');
log-line($fh, 'done');
$fh.close;

print slurp 'log.txt';
```

🦋 Исходный код можно найти в файле [pass-a-handle.raku](https://github.com/ash/raku-course/blob/master/exercises/oop/file-handles/pass-a-handle.raku).

## Вывод

```
started
working
done
```

## Комментарии

1. Дескриптор, который возвращает `open`, — это просто значение, которое хранится в `$fh`. Поэтому он может быть аргументом `log-line`, как любая строка или число. Внутри подпрограммы `$fh.say` пишет через тот же самый открытый дескриптор.

1. Дескриптор остаётся открытым во время всех трёх вызовов. Поэтому каждый `log-line` добавляет ещё одну строку в конец того же файла. Затем `close` сохраняет всё на диске, а `slurp` читает три строки обратно.

1. Именно поэтому дескрипторы легко сочетать. Функция может принять дескриптор и писать в него или читать из него. Ей неважно, на какой файл указывает дескриптор. Это решает код, который вызывает функцию, когда открывает файл.
