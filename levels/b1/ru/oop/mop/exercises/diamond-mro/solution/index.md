Вот одно возможное решение.

## Код

```raku
class A {
}

class B is A {
}

class C is A {
}

class D is B is C {
}

say D.^mro.map(*.^name);
```

🦋 Исходный код можно найти в файле [diamond-mro.raku](https://github.com/ash/raku-course/blob/master/exercises/oop/mop/diamond-mro.raku).

## Вывод

```
(D B C A Any Mu)
```

## Комментарии

1. `D` наследует сразу от двух родителей: `class D is B is C` перечисляет каждого из них со своим `is`. Это множественное наследование. Вместе `A`, `B`, `C` и `D` образуют *ромб*. От `D` вверх к общему предку `A` ведут два пути.

1. `.^mro` превращает ромб в один прямой порядок поиска. Сначала идёт `D`, затем его родители `B` и `C` в том порядке, в котором вы их написали. Потом идёт общий `A` и, наконец, `Any` и `Mu`.

1. И `B`, и `C` ведут к `A`. И всё же тип `A` появляется только **один раз** и только после них обоих. В этом и смысл порядка разрешения методов. Каждый тип посещается ровно один раз. И родитель никогда не идёт раньше потомка, который от него наследует. Поэтому Raku всегда находит метод в `B` раньше того, который он переопределяет в `A`.
