`spurt` и `mkdir` создают что-то на диске, а две другие процедуры это удаляют.

Процедура `unlink` удаляет файл:

```raku
spurt 'temp.txt', 'scratch data';
say 'temp.txt'.IO.e; # True

unlink 'temp.txt';
say 'temp.txt'.IO.e; # False
```

`unlink` удаляет файл с указанным именем. Как и у других процедур для файловой системы, у неё есть и форма метода. Её вызывают у объекта пути: `'temp.txt'.IO.unlink`.

Удаление происходит сразу и навсегда. Нет корзины, из которой можно вернуть файл. Заметьте ещё одну вещь об удалённом файле. Проверять его нужно через `.e` (существование), а не через `.f`. Проверки типа `.f` и `.d` выдают ошибку, если пути нет.

Процедура `rmdir` удаляет каталог, но только **пустой**:

```raku
mkdir 'reports';
rmdir 'reports';
say 'reports'.IO.e; # False
```

Если в каталоге ещё что-то есть, `rmdir` ничего не удаляет. Каталог остаётся на месте. Поэтому, чтобы удалить каталог с файлами, сначала очистите его, а потом удалите:

```raku
mkdir 'reports';
spurt 'reports/jan.txt', 'January';
spurt 'reports/feb.txt', 'February';

.unlink for 'reports'.IO.dir;   # удаляем все записи
rmdir 'reports';                # теперь каталог пуст
say 'reports'.IO.e;             # False
```

`'reports'.IO.dir` выдаёт список записей каталога, как вы видели в предыдущей теме. Вызов `.unlink` у каждой записи удаляет её. Когда каталог пуст, `rmdir` может его удалить. Заметьте, что этот простой цикл ожидает в каталоге только файлы. Для дерева вложенных подкаталогов понадобилась бы рекурсия, чтобы сначала очистить их.
