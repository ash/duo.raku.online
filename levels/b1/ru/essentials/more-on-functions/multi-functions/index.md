В Raku есть _множественная диспетчеризация_ на основе сигнатуры функции. Она позволяет создавать функции с одним именем, но с разными типами входных данных. Используйте декларатор `multi` для каждого варианта функции.

```raku
multi sub add(Int $x, Int $y) { $x + $y }
multi sub add(Str $x, Str $y) { $x ~ $y }
```

После `multi` вполне можно не писать `sub`.

Когда у одной и той же функции два варианта, компилятор выполняет множественную диспетчеризацию. Его выбор зависит от того, какие аргументы он видит в вызове функции. Сравните эти два вызова:

```raku
say add(10, 20); # 30
say add('10', '20'); # 1020
```

Первый вызов запускает вариант с целочисленными параметрами. Второй вызов запускает другой вариант, который ожидает две строки.

## Литеральные параметры

Интересное применение многофункций — варианты с литеральными значениями в качестве параметров. Посмотрите на следующие два варианта:

```raku
multi sub f(42) {say 'Это ответ'}
multi sub f($x) {say "$x не является ответом"}
```

Первый вариант выполняется, только когда вы вызываете функцию ровно с 42. Во всех других случаях Raku использует второй вариант. Не важно, в каком порядке определены эти функции.

```raku
f(10); # 10 не является ответом
f(42); # Это ответ
```
