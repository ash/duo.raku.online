Наречие `:exists` превращает обращение по индексу в вопрос. Есть ли значение по этому ключу или индексу? Наречие возвращает логическое значение, но не получает само значение:

```raku
my %h = apple => 1, pear => 2;

say %h<apple>:exists; # True
say %h<plum>:exists;  # False
```

Это правильный способ проверить ключ. Если просто прочитать `%h<plum>`, вы получите неопределённое значение. В зависимости от данных это может скрыть разницу между «отсутствует» и «есть, но не определён».

Наречие `:delete` удаляет запись и возвращает вам её значение:

```raku
my %h = apple => 1, pear => 2;

say %h<apple>:delete; # 1
say %h.keys;          # (pear)
say %h;               # {pear => 2}
```

Записи `apple` больше нет. Вы получаете обратно удалённое значение `1`, поэтому можете его использовать.

Оба наречия работают и с массивами — по индексу:

```raku
my @a = 10, 20, 30;

say @a[1]:exists; # True
say @a[5]:exists; # False

say @a[1]:delete; # 20
say @a[1]:exists; # False
```

Как выглядит массив, когда из его середины удалён элемент? Вот ответ:

```raku
say @a; # [10 (Any) 30]
```

Итак, одна единая запись позволяет проверять и менять контейнеры на месте. Отдельные методы для этого не нужны.
