Ещё два контекста решают, будет ли что-то **списком** или одним **элементом**. В списке несколько значений. На этой разнице основаны сигилы `@` и `$`.

В _контексте списка_ массив раскладывается на свои элементы. Цикл `for` помещает свой аргумент в контекст списка, поэтому он проходит по каждому элементу:

```raku
my @a = 1, 2, 3;

my $count = 0;
$count++ for @a;
say $count; # 3
```

В _контексте элемента_ тот же массив ведёт себя как одно значение. Контекстуализатор `$( … )` задаёт контекст элемента. Поэтому теперь цикл видит только одну вещь и выполняется один раз:

```raku
my @a = 1, 2, 3;

my $count = 0;
$count++ for $(@a);
say $count; # 1
```

Это объясняет, что происходит, когда вы присваиваете массив скаляру. Массив упаковывается в один элемент, и его элементы не копируются. Причина в том, что `my $x = @a` помещает `@a` в контекст элемента. Обратите внимание, что этот один элемент может быть другим контейнером с множеством элементов внутри:

```raku
my @a = 1, 2, 3;

my $var = @a;
say $var;      # [1 2 3]
say $var.WHAT; # (Array)
```

Переменная `$var` — это скалярный контейнер, поэтому теперь она содержит один объект. Этот объект — `Array`. Это легко доказать. Используйте `$var` как своего рода ссылку на массив, как это назвали бы в других языках:

```raku
say $var[1]; # 2
```

Его пара, контекстуализатор `@( … )`, делает обратное и задаёт контекст списка.

Есть также _контекст поглощения (sink context)_. Это контекст выражения, значение которого выбрасывается. Например, строка кода может быть нужна только ради побочного эффекта. Иногда значение в контексте поглощения не делает ничего полезного. Тогда Raku может предупредить о «бесполезном использовании» (useless use). Это полезная подсказка, что вы забыли использовать результат.

Когда вы выбираете сигил, `$` или `@`, вы на самом деле выбираете контекст. Где нужно, контекстуализаторы `$( )` и `@( )` позволяют его изменить.
