title: Динамические переменные
---

У _динамической_ переменной есть твигил `*`. Лексическая переменная видна только в блоке, где вы её объявили. Динамическая переменная работает иначе: Raku находит её, когда ищет **вверх по стеку вызовов**. Он ищет в коде, который вызвал текущий код. Неважно, где этот код определён.

```raku
my $*greeting = 'Hello';

sub greet {
    say $*greeting;
}

greet(); # Hello
```

Подпрограмма `greet` не объявляет `$*greeting` и не получает её как аргумент. Но она всё равно её видит. Это потому, что переменная динамическая. Кроме того, `greet` вызвали из места, где эта переменная находится в области видимости.

Этот пример работал бы и с простой глобальной скалярной переменной `$greeting`. Но следующий пример показывает, что делает динамические переменные особенными.

Поиск идёт по стеку вызовов. Поэтому более близкое объявление **перекрывает** более далёкое, пока работает его блок:

```raku
my $*level = 'outer';

sub show {
    say $*level;
}

show(); # outer

{
    my $*level = 'inner';
    show(); # inner
}
```

Одна и та же `show` в первый раз печатает `outer`. Она печатает `inner`, когда её вызывают изнутри блока, который снова объявил `$*level`. Это _динамическая область видимости_. Встроенные переменные Raku `$*OUT`, `$*IN` и `$*ERR` работают так же. Можно на время перенаправить вывод, если снова объявить `$*OUT` в блоке. Тогда каждая подпрограмма, которую вы вызываете внутри блока, видит новое значение. Динамические переменные отлично подходят, чтобы передавать контекст в вызываемый код без явного аргумента.
