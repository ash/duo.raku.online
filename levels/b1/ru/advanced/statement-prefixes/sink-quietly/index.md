Ещё два префикса нужны, чтобы выполнять код ради его эффектов, а не ради его значения.

Префикс `sink` выполняет что-то в _контексте sink_, то есть только ради побочных эффектов. Результат выбрасывается. Это полезно, когда нужно заставить ленивую операцию выполниться:

```raku
sink (1..3).map({ print "$_ " });
print "\n"; # 1 2 3
```

Здесь `map` выполняется только ради печати, которую он делает. `sink` гарантирует, что он действительно выполнится, а потом выбрасывает полученный список. Если ничто его не заставляет, ленивый `map` может вообще не запуститься. Так бывает, когда его результат никогда не используется.

Префикс `quietly` выполняет блок с **выключенными предупреждениями**. Код, который обычно печатает предупреждение в поток ошибок, молчит:

```raku
my $value;
quietly {
    say $value + 1; # 1, без предупреждения "uninitialized value"
}
```

Если прибавить `1` к неопределённому `$value`, обычно появляется предупреждение о неинициализированном значении. Внутри `quietly` это предупреждение скрыто. Используйте его, когда вы знаете, что код выдаёт предупреждение, и не хотите лишнего шума. Но делайте это редко, потому что предупреждения обычно указывают на настоящую ошибку.
