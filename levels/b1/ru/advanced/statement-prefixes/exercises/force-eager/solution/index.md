Вот одно возможное решение.

## Код

```raku
say (1 .. Inf).is-lazy;
say (eager 1..3).is-lazy;
say (lazy 1..3).is-lazy;
```

🦋 Исходный код можно найти в файле [force-eager.raku](https://github.com/ash/raku-course/blob/master/exercises/advanced/statement-prefixes/force-eager.raku).

## Вывод

```
True
False
True
```

## Комментарии

1. Диапазон до `Inf` нельзя вычислить целиком, поэтому он ленивый. `.is-lazy` возвращает `True`.

1. Префикс `eager` заставляет Raku создать список сразу. Поэтому результат больше не ленивый. `.is-lazy` возвращает `False`. Это прямая противоположность тому, чтобы пометить список как `lazy`.

1. Не используйте `eager` с диапазоном, у которого нет конца. `eager 1 .. Inf` пытается вычислить каждый элемент сразу. Поэтому программа просто зависает и занимает всё больше памяти, пока её не остановят принудительно. `eager` безопасен только со списками, которые точно конечны.

1. Обратное тоже работает. `lazy 1..3` помечает как ленивый даже короткий конечный диапазон, поэтому `.is-lazy` возвращает `True`. Префикс ставит флаг ленивости, каким бы маленьким ни был список. Списку не обязательно быть бесконечным, чтобы быть ленивым.
