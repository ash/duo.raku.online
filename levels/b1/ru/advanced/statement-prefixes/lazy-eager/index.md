Некоторые списки в Raku вычисляются только тогда, когда нужны их элементы. Такие списки называют _ленивыми_. Префиксы `lazy` и `eager` позволяют управлять этим напрямую.

Префикс `eager` заставляет Raku создать список **целиком**, сразу же:

```raku
my @squares = eager (1..3).map(* ** 2);
say @squares; # [1 4 9]
```

Без `eager` `map` всё равно создал бы значения. Но `eager` гарантирует, что все они вычисляются сразу, а не позже по запросу.

Префикс `lazy` делает обратное. Он помечает список как ленивый. Тогда его элементы создаются только тогда, когда код их запрашивает. Именно это позволяет списку быть бесконечным, хотя бы в теории:

```raku
my $numbers = lazy (1 .. Inf);
say $numbers.is-lazy; # True
```

Метод `.is-lazy` это подтверждает. Список не будет пытаться заранее вычислить все свои бесконечные элементы.

Однако в этом примере Raku и так сделал бы список ленивым. Диапазон без конца, например `1 .. Inf`, уже ленивый. Поэтому `say (1 .. Inf).is-lazy` печатает `True` и без префикса. Слово `lazy` здесь ничего не меняет. Оно только ясно показывает ваше намерение. Префикс по-настоящему полезен для списка, который Raku иначе вычислил бы нетерпеливо. С `lazy` такой список можно сделать ленивым.

Чаще всего Raku сам делает хороший выбор. Диапазоны и последовательности ленивые, а обычное присваивание массиву — нетерпеливое. Используйте эти префиксы, когда нужно изменить этот выбор. Используйте `eager`, чтобы дорогое вычисление произошло сейчас. Используйте `lazy`, чтобы отложить вычисление, которое может быть большим или бесконечным.
