Если пометить подпрограмму как `is export`, она попадает в группу экспорта модуля _по умолчанию_. Это имена, которые подключает простой `use`. Также можно дать `is export` _тег_. Теги распределяют экспорты по группам с именами. Тогда каждая программа может выбрать нужную ей группу.

Тег записывается в скобках после `is export`:

```raku
unit module Greeting;

sub hello($name)   is export            { "Hello, $name!" }
sub goodbye($name) is export(:partings) { "Goodbye, $name!" }
```

У `hello` нет тега, поэтому она относится к группе по умолчанию. У `goodbye` есть тег `:partings`.

Простой `use` импортирует только группу по умолчанию:

```raku
use Greeting;      # hello is available; goodbye is not
```

Если указать тег, `use` импортирует вместо этого группу тега. Возможно, это вас удивит, но группу по умолчанию он при этом _не_ импортирует:

```raku
use Greeting :partings; # goodbye is available; hello is not
```

Когда вы запрашиваете `:partings`, вы получаете именно эту группу. Чтобы импортировать всё, что экспортирует модуль, используйте встроенный тег `:ALL`:

```raku
use Greeting :ALL; # both hello and goodbye
```

Есть два особых тега, которые полезно знать. Каждый модуль поддерживает `:ALL`, который импортирует все его экспорты. `:MANDATORY` можно поставить на подпрограмму, которую нужно импортировать всегда. Неважно, какой тег выберет вызывающий код.

На самом деле каждый тег — это пакет внутри пакета `EXPORT` модуля, например `Greeting::EXPORT::partings`. Именно такие пакеты показывает [интроспекция модулей](/ru/advanced/module-introspection). С тегами большой модуль может оставить свой набор экспортов по умолчанию маленьким. При этом он всё равно может дать дополнительные возможности, когда программа их просит.
