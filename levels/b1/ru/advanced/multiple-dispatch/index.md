В разделе «Основы» вы познакомились с [_мульти-функциями_](/ru/essentials/more-on-functions/multi-functions). Это несколько подпрограмм с одним именем. Raku выбирает нужную, глядя на типы аргументов. Это называется _множественная диспетчеризация_.

До сих пор Raku выбирал по _типу_ аргументов. Конструкция `where` позволяет пойти дальше и выбирать также по _значению_. Её пишут после параметра, и она содержит условие. Аргумент должен подходить под это условие, иначе этого кандидата не выберут:

```raku
multi sub info(Int $n where $n < 0)  { say "$n is negative" }
multi sub info(Int $n where $n == 0) { say "$n is zero" }
multi sub info(Int $n where $n > 0)  { say "$n is positive" }

info(-5);
info(0);
info(7);
```

Каждый вызов запускает того кандидата, чьё условие истинно для данного значения:

```
-5 is negative
0 is zero
7 is positive
```

Если смотреть только на типы, у всех трёх кандидатов одна и та же сигнатура: один `Int`. Поэтому без конструкций `where` они бы конфликтовали. Условия отличают их друг от друга.

## Базовый случай для рекурсии

`where` часто используют для точки остановки рекурсии. Эта точка получает своего отдельного кандидата. Вот снова факториал, теперь в виде двух мульти-подпрограмм:

```raku
multi sub fact(Int $n where $n <= 1) { 1 }
multi sub fact(Int $n)               { $n * fact($n - 1) }

say fact(5); # 120
```

Первый кандидат обрабатывает базовый случай, когда `$n` равно `1` или меньше. Он просто возвращает `1`. Все остальные значения попадают ко второму кандидату. Он снова вызывает `fact` с меньшим числом. Внутри функции нет никакого `if`. Выбор между базовым случаем и рекурсивным шагом делает диспетчер.
