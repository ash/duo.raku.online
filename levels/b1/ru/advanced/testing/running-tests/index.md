Отдельный тестовый файл — это просто программа на Raku. Поэтому его можно запустить напрямую:

```
raku t/01-basic.rakutest
```

Он печатает на экран результат в формате TAP. Когда у вас больше одного-двух файлов, нужно _средство запуска тестов_. Оно запускает целую директорию тестов и даёт сводку результатов. Для Raku такое средство — `prove6`:

```
prove6 t/
```

Эта команда запускает все тестовые файлы в `t/` и сообщает, сколько файлов и тестов прошло. В конце есть один общий результат: успех или неудача. Это читать гораздо легче, чем необработанный TAP каждого файла.

Если у дистрибутива есть `META6.json`, инструмент управления модулями может запустить его тесты за вас:

```
zef test .
```

`zef test` находит директорию `t/`, запускает тесты и сообщает результат. Точно то же самое происходит автоматически перед установкой дистрибутива. Поэтому у тестов две задачи. Вы запускаете их с помощью `prove6` во время разработки. Экосистема запускает их, чтобы проверить дистрибутив, прежде чем кто-то его установит.

> Тестовые файлы имеют расширение `.rakutest` (или `.t`). Обычно в их именах есть номера, как в `t/01-basic.rakutest`.
