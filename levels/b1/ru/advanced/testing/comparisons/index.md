Кроме `ok` и `is`, в модуле `Test` есть функции сравнения для разных видов значений. Вот самые полезные из них:

* `is` — проверяет, равны ли два значения (как строки или числа)
* `is-deeply` — проверяет, что две структуры данных точно равны, включая их типы
* `like` — проверяет, что строка соответствует регулярному выражению
* `isnt` — проходит, когда два значения **не** равны

`is-deeply` — правильный выбор для массивов, хэшей и вложенных данных. Он точно сравнивает и структуру, и тип:

```raku
use Test;

my @reversed = (1, 2, 3).reverse;
is-deeply @reversed, [3, 2, 1], 'reversed';

done-testing;
```

Вывод:

```
ok 1 - reversed
1..1
```

`is` превратил бы значения в строки и сравнил бы их нестрого. Но `is-deeply` требует, чтобы структуры действительно совпадали. Обратите внимание, что `done-testing` ставит план `1..1` в конец, после проверки.

Не обязательно позволять `done-testing` считать тесты за вас. Вместо этого можно указать их число в начале с помощью `plan`. Это защищает от тестового файла, который завершается раньше времени и молча пропускает некоторые проверки:

```raku
use Test;

plan 2;
ok True,  'first';
ok 1 < 2, 'second';
```

На этот раз план стоит **первым**, перед результатами:

```
1..2
ok 1 - first
ok 2 - second
```

Вот отличие от `done-testing`, которое можно увидеть. `plan` печатает количество `1..2` вверху, до начала всех проверок. А `done-testing` печатает его в самом конце. В любом случае при `plan 2` запуск ожидает ровно два теста. Если запустится меньше или больше тестов, набор тестов будет считаться неудачным. Используйте `plan`, когда число тестов постоянно и известно. Используйте `done-testing`, когда проще дать фреймворку для тестов посчитать самому.
