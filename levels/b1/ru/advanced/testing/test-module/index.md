Вы загружаете инструменты для тестирования с помощью `use Test`. Самая базовая проверка — `ok`, которая проходит, когда её условие истинно. Каждая проверка может также принимать описание:

```raku
use Test;

ok 1 == 1, 'one equals one';
ok 2 > 1,  'two is greater';

done-testing;
```

Если её запустить, она выведет это в стандартном формате тестов, который называется _TAP_:

```
ok 1 - one equals one
ok 2 - two is greater
1..2
```

Каждая проверка, которая прошла, показана как `ok` с номером и описанием. Проверка, которая не прошла, показала бы `not ok`. Последняя строка, `1..2`, — это _план_, который говорит, сколько тестов было выполнено. Вызов `done-testing` в конце печатает этот план автоматически.

Когда вы ожидаете определённое значение, `is` понятнее, чем `ok`. Если тест не проходит, `is` показывает и ожидаемое, и фактическое значение:

```raku
use Test;

is 2 + 2, 4, 'addition works';

done-testing;
```

Эта программа выводит `ok 1 - addition works`. Чтобы увидеть, как `is` сообщает о проблеме, передайте ему неверное ожидаемое значение:

```raku
use Test;

is 2 + 2, 5, 'addition works';

done-testing;
```

Теперь проверка не проходит, и вывод точно объясняет, что пошло не так:

```
not ok 1 - addition works
# Failed test 'addition works'
# at test.raku line 3
# expected: '5'
#      got: '4'
1..1
# You failed 1 test of 1
```

Строка `not ok` отмечает неудачу. Строки под ней показывают, что ожидалось и что программа получила на самом деле. Поэтому, когда важно определённое значение, `is` полезнее, чем простой `ok`.

`ok`, `is` и `done-testing` — этого уже достаточно для полезного тестового файла. Следующая тема добавляет [другие виды сравнений](/ru/advanced/testing/comparisons).
