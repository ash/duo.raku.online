Имя модуля создаёт _пакет_. Пакет — это пространство имён, в котором хранятся имена, объявленные в модуле. Раньше, в [разделе о контейнерах](/ru/advanced/containers), вы познакомились с `WHO`. Он возвращает `Stash` пакета, то есть его таблицу символов. Интроспекция модулей использует именно это.

В примерах ниже используется модуль `Greeting`, который мы создали в прошлых темах. В нём есть экспортированная подпрограмма и общая переменная `our`:

```raku
unit module Greeting;

our $version = '1.0';

sub hello($name) is export {
    return "Hello, $name!";
}
```

Пакет модуля записывают с `::` в конце. Если добавить `.keys`, получится список имён, которые в нём есть:

```raku
use Greeting;

say Greeting::.keys.sort; # ($version EXPORT)
```

Модуль `Greeting` из прошлых тем объявляет переменную `our` — `$version`. Поэтому его пакет содержит это имя вместе с сигилом. Рядом с ним стоит `EXPORT`, и это может показаться странным. Это пакет, который Raku создаёт автоматически. В нём хранится всё, что модуль помечает как `is export`, например подпрограмма `hello`. Поэтому экспортированное имя _не_ появляется прямо в пакете. Оно находится внутри подпакета `EXPORT`. Ключи могут возвращаться в разном порядке. Поэтому пример их сортирует, чтобы результат всегда был одинаковым.

Также можно найти имя в пакете. Просто используйте имя как ключ. Это даёт то же значение, что и полное имя `$Greeting::version`:

```raku
use Greeting;

say Greeting::{'$version'}; # 1.0
```

## Список экспортируемых имён модуля

Экспортированные имена на самом деле находятся в пакете `EXPORT`, который вы видели выше. Поэтому их можно перечислить, если заглянуть на один уровень глубже. Экспорты без тега попадают в группу `DEFAULT` (смотрите [Теги экспорта](/ru/advanced/modules-basics/export-tags)). `.keys` этой группы — это экспортированные подпрограммы:

```raku
use Greeting;

say Greeting::EXPORT::DEFAULT::.keys.sort; # (&hello)
```

Каждый ключ — это экспортированное имя вместе с сигилом. Здесь это единственная подпрограмма `&hello` со знаком `&`, который обозначает подпрограмму. Так можно узнать, что модуль предлагает своим пользователям. Вам не нужно читать его исходный код. Просто спросите у его пакета `EXPORT::DEFAULT`, что в нём хранится.

Заглядывать внутрь пакета таким способом полезно в двух случаях. Может быть, вы хотите узнать, что предоставляет модуль. Или вы хотите обращаться к его именам во время работы программы. Тогда не нужно выписывать каждое имя в исходном коде.
