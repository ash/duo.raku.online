_Прагма_ выглядит как модуль, который вы загружаете с помощью `use`. Но она не подключает никакого кода. Вместо этого она меняет правило компиляции для остальной части текущей области видимости. Её включают с помощью `use`, а там, где это имеет смысл, выключают с помощью `no`.

Самая важная прагма, `strict`, в Raku **включена по умолчанию**. Она требует, чтобы вы объявляли каждую переменную перед использованием. Поэтому Raku замечает опечатку в имени переменной. Без неё опечатка молча создала бы новую переменную.

Если выключить `strict` с помощью `no strict`, это правило больше не действует. Тогда можно присвоить значение переменной, которая никогда не была объявлена с `my`:

```raku
no strict;

$x = 42;
say $x; # 42
```

С включённой по умолчанию `strict` такое `$x = 42` без объявления было бы ошибкой компиляции. Сообщение такое: *Variable '$x' is not declared*. Строка `no strict` ослабляет правило до конца окружающей области видимости.

Другие прагмы — это `fatal`, `isms` и `variables`. `fatal` превращает тихую ошибку в выброшенное исключение. Это полезно, когда вы уже знаете, как обрабатывать исключения. `isms` разрешает способы записи, которые пришли из других языков. `variables` позволяет настраивать правила для переменных. Действие прагмы _лексическое_. Оно длится только до конца блока, в котором она стоит. Поэтому правило можно сделать строже или мягче. Это можно сделать именно в той части кода, где это нужно.

Одна прагма принимает аргумент: `lib`. Она добавляет каталог в список, в котором Raku ищет модули при загрузке. Она делает то же самое, что параметр командной строки `-I`, но внутри программы:

```raku
use lib 'lib';
```

Вы начнёте её использовать, когда станете писать и загружать собственные [модули](/ru/advanced/modules-basics/using-modules).
