Кроме простого `int`, в Raku есть целые числа с фиксированным размером в битах. Это `int8`, `int16`, `int32`, `int64` и их беззнаковые пары `uint8`, `uint16`, `uint32`, `uint64`. Число показывает, сколько битов занимает значение.

Когда размер в битах фиксирован, диапазон тоже фиксирован. `int8` хранит значения от `-128` до `127`, а `uint8` — от `0` до `255`. Хранилище не может расти, поэтому выход за верхнюю границу ведёт по кругу к нижней. Это называется _переполнением_:

```raku
my int8 $i = 127;
$i++;
say $i; # -128
```

Если прибавить единицу к наибольшему `int8`, вы не получите `128`. Это число не поместилось бы. Вместо этого значение по кругу переходит к наименьшему, `-128`. Беззнаковые типы тоже идут по кругу:

```raku
my uint8 $u = 255;
$u++;
say $u; # 0
```

Обычный `Int` — противоположность. Он просто растёт до нужного размера и никогда не переполняется. В таком обмене и есть весь смысл нативных типов фиксированного размера. Вы соглашаетесь на фиксированный диапазон. Взамен вы получаете предсказуемое, небольшое и быстрое хранение.

Вы знаете диапазон своих данных и хотите эффективности? Тогда используйте нативный тип фиксированного размера. Например, храните байты двоичных данных в массиве `uint8`. Для обычной арифметики, где числа могут расти без предела, используйте `Int`.
