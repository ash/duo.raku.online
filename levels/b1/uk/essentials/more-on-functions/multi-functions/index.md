У Raku є _множинна диспетчеризація_ на основі сигнатури функції. Вона дає змогу створювати функції з однаковою назвою, але з різними типами вхідних даних. Використовуйте декларацію `multi` для кожного варіанта функції.

```raku
multi sub add(Int $x, Int $y) { $x + $y }
multi sub add(Str $x, Str $y) { $x ~ $y }
```

Цілком нормально опустити `sub` після `multi`.

Коли є два варіанти однієї функції, компілятор виконує множинну диспетчеризацію. Його вибір залежить від того, які аргументи він бачить у виклику функції. Порівняйте ці два виклики:

```raku
say add(10, 20); # 30
say add('10', '20'); # 1020
```

Перший виклик запускає варіант із цілими параметрами. Другий виклик запускає інший варіант, який очікує два рядки.

## Літеральні параметри

Цікаве застосування багатофункцій — варіанти з літеральними значеннями як параметрами. Подивіться на наступні два варіанти:

```raku
multi sub f(42) {say 'Це відповідь'}
multi sub f($x) {say "$x не є відповіддю"}
```

Перший варіант працює, лише коли ви викликаєте функцію саме з 42. В усіх інших випадках Raku використовує другий варіант. Не має значення, в якому порядку визначені ці функції.

```raku
f(10); # 10 не є відповіддю
f(42); # Це відповідь
```
