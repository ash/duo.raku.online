Коли в програмі на Raku щось іде не так, кидається _виняток_. Це стається, наприклад, коли бракує файлу або коли ви самі викликаєте `die`. За замовчуванням виняток, який ніхто не обробляє, зупиняє програму. Блок `try` дозволяє виконати код, який може не спрацювати, без падіння програми.

Ви кладете ризикований код у блок `try`. Якщо всередині нього кинуто виняток, блок зупиняється в цьому місці. Але програма працює далі:

```raku
my $result = try {
    die 'Boom!';
};

say "Still works";
```

Блок `try` перехоплює `die`, тож програма не падає. Вона одразу переходить до наступного оператора й виводить:

```
Still works
```

Коли блок отак не спрацьовує, він дає невизначене значення. Тож змінна `$result` невизначена:

```raku
say $result.defined; # False
```

Перехоплений виняток зберігається в спеціальній змінній `$!`. Звідти можна прочитати його повідомлення:

```raku
say $!.message; # Boom!
```

Отже, `try` робить із фатальної помилки те, що ваша програма може перевірити й на що може відреагувати. Якщо блок виконується без жодного винятку, `$result` містить його значення, а `$!` невизначена.
