Роль не обов'язково вбудовувати в клас. Її можна надати й об'єкту, який уже існує, за допомогою оператора `but`. Він підмішує роль в один об'єкт під час виконання. Потім він повертає новий об'єкт, який має цю роль:

```raku
role Loud {
    method greet {
        callsame().uc;
    }
}

class Greeter {
    method greet {
        'Hello';
    }
}

my $quiet = Greeter.new;
my $loud  = Greeter.new but Loud;

say $quiet.greet; # Hello
say $loud.greet;  # HELLO
```

Роль отримав лише `$loud`. Клас `Greeter` і всі інші об'єкти `Greeter` лишаються такими самими. Тож `$quiet` і далі вітається у звичайний спосіб. Іноді і роль, і клас визначають метод з однаковим іменем. У такому разі перемагає версія ролі. А `callsame` викликає метод, який вона перевизначила. Тут це початковий `greet` із `Greeter`. Його результат потім переводять у верхній регістр.

Вважається, що об'єкт із підмішаною роллю виконує цю роль:

```raku
say $quiet ~~ Loud; # False
say $loud  ~~ Loud; # True
```

`but` лишає початковий об'єкт таким, яким він був, і дає вам новий. Якщо ви хочете змінити сам наявний об'єкт, використайте натомість оператор `does`:

```raku
my $speaker = Greeter.new;
$speaker does Loud;
say $speaker.greet; # HELLO
```

Коли ви підмішуєте ролі в окремі об'єкти, ви вирішуєте, яку додаткову поведінку отримує кожен об'єкт. Вам не треба визначати окремий клас для кожного поєднання.
