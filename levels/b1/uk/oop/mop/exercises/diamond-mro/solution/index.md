Ось один із можливих розв'язків.

## Код

```raku
class A {
}

class B is A {
}

class C is A {
}

class D is B is C {
}

say D.^mro.map(*.^name);
```

🦋 Вихідний код можна знайти у файлі [diamond-mro.raku](https://github.com/ash/raku-course/blob/master/exercises/oop/mop/diamond-mro.raku).

## Вивід

```
(D B C A Any Mu)
```

## Коментарі

1. `D` успадковує одразу від двох батьків: `class D is B is C` перелічує кожного з власним `is`. Це множинне успадкування. Разом `A`, `B`, `C` і `D` утворюють *ромб*. Від `D` угору до спільного предка `A` ведуть два шляхи.

1. `.^mro` перетворює ромб на один прямий порядок пошуку. Першим іде `D`, потім його батьки `B` та `C` у тому порядку, в якому ви їх написали. Потім іде спільний `A`, і нарешті `Any` та `Mu`.

1. І `B`, і `C` ведуть до `A`. Проте тип `A` з'являється лише **один раз**, і лише після них обох. У цьому й полягає суть порядку розв'язання методів. Кожен тип відвідують рівно один раз. І батько ніколи не стоїть перед дитиною, яка від нього успадковує. Тож Raku завжди знаходить метод у `B` раніше за той, який він перевизначає в `A`.
