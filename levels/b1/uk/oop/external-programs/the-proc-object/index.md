Кожен виклик `run` чи `shell` повертає об'єкт `Proc`. Це невеликий запис, який описує, яка програма виконувалася і як вона завершилася. У попередніх темах ми читали вивід через його дескриптор `.out`. Але `Proc` містить більше, ніж це.

Найкорисніша частина — це **код завершення**. Невеликим цілим числом програма повідомляє тому, хто її запустив, чи вона спрацювала. `0` означає успіх. Будь-яке інше число — це код невдачі, який програма вибирає сама. `.exitcode` дає вам це число:

```raku
my $proc = run 'sh', '-c', 'exit 3';
say $proc.exitcode; # 3
```

Зазвичай ви ставите лише запитання «так чи ні»: чи спрацювало? Для цього `Proc` просто істинний, коли код завершення дорівнює `0`. Інакше він хибний. Тож його можна перевіряти напряму:

```raku
my $proc = run 'ls', '/', :out;
$proc.out.slurp(:close);
say $proc ?? 'ok' !! 'failed'; # ok
```

`Proc` також пам'ятає, яку команду він запустив, у `.command`:

```raku
my $proc = run 'echo', 'hi', :out;
$proc.out.slurp(:close);
say $proc.command; # (echo hi)
```

Тут є одна річ, на яку варто зважати. Якщо команда не спрацювала, а ви просто **ігноруєте** повернений `Proc`, Raku кидає виняток. Він не дає збою пройти непоміченим:

```raku
run 'sh', '-c', 'exit 1';
# гине: The spawned command 'sh' exited unsuccessfully (exit code: 1, signal: 0)
```

Ненульовий код завершення зазвичай означає, що щось пішло не так. Тож якщо ви викидаєте невдалий `Proc`, він кидає виняток. Це стається, коли він виходить за межі області видимості. Причина тут — саме *викидання* результату, а не те, що ви не дивитеся на код завершення. Досить просто зберегти `Proc` у змінній, щоб уникнути винятку. Вам навіть не треба знову на нього дивитися.

```raku
my $proc = run 'sh', '-c', 'exit 1'; # помилки немає, хоч команда й зазнала невдачі
# …і $proc більше ніколи не використовується
```

Тож якщо ви *очікуєте*, що команда може не спрацювати, збережіть її `Proc`. Потім погляньте на `.exitcode` або перевірте його як булеве значення. Робіть це щоразу, коли хочете дізнатися, що сталося.
