Якщо позначити підпрограму як `is export`, вона потрапить до _типової_ групи експорту модуля. Це імена, які приносить звичайний `use`. Також ви можете дати `is export` _мітку_. Мітки розкладають експорти по іменованих групах. Тоді кожна програма може обрати потрібну їй групу.

Мітку записують у дужках після `is export`:

```raku
unit module Greeting;

sub hello($name)   is export            { "Hello, $name!" }
sub goodbye($name) is export(:partings) { "Goodbye, $name!" }
```

`hello` не має мітки, тож належить до типової групи. `goodbye` має мітку `:partings`.

Звичайний `use` імпортує лише типову групу:

```raku
use Greeting;      # hello доступна; goodbye ні
```

Якщо назвати мітку, `use` імпортує натомість цю групу. Можливо, це несподівано, але типову групу він при цьому _не_ імпортує:

```raku
use Greeting :partings; # goodbye доступна; hello ні
```

Коли ви просите `:partings`, ви отримуєте саме цю групу. Щоб імпортувати все, що експортує модуль, скористайтеся вбудованою міткою `:ALL`:

```raku
use Greeting :ALL; # і hello, і goodbye
```

Є дві особливі мітки, які корисно знати. Кожен модуль підтримує `:ALL`, яка імпортує всі його експорти. Ви можете поставити `:MANDATORY` на підпрограму, яка має імпортуватися завжди. Неважливо, яку мітку обере програма, що використовує модуль.

Кожна мітка насправді є пакунком усередині пакунка `EXPORT` модуля, наприклад, `Greeting::EXPORT::partings`. Саме це перелічує [інтроспекція модулів](/uk/advanced/module-introspection). Завдяки міткам більший модуль може тримати свій типовий набір експортів невеликим. Водночас він може пропонувати додаткові можливості, коли програма їх просить.
