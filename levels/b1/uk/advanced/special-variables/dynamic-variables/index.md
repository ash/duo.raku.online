_Динамічна_ змінна має твіґіл `*`. Лексична змінна видима лише в тому блоці, де ви її оголошуєте. Динамічна змінна інша: Raku знаходить її, дивлячись **назовні по стеку викликів**. Він шукає в коді, який викликав поточний код. Неважливо, де цей код визначено.

```raku
my $*greeting = 'Hello';

sub greet {
    say $*greeting;
}

greet(); # Hello
```

Підпрограма `greet` не оголошує `$*greeting` і не отримує її як аргумент. Але вона все одно її бачить. Це тому, що змінна динамічна. Крім того, `greet` викликано з місця, де ця змінна в області видимості.

Цей приклад працював би і з простою глобальною скалярною змінною `$greeting`. Але наступний приклад показує, чим особливі динамічні змінні.

Пошук іде за стеком викликів. Тож ближче оголошення **перекриває** дальше, поки виконується його блок:

```raku
my $*level = 'outer';

sub show {
    say $*level;
}

show(); # outer

{
    my $*level = 'inner';
    show(); # inner
}
```

Той самий `show` першого разу виводить `outer`. Він виводить `inner`, коли його викликають зсередини блоку, який знову оголосив `$*level`. Це _динамічна область видимості_. Вбудовані `$*OUT`, `$*IN` та `$*ERR` у Raku працюють так само. Ви можете на якийсь час перенаправити вивід, якщо знову оголосите `$*OUT` у блоці. Тоді кожна підпрограма, яку ви викликаєте в цьому блоці, бачить нове значення. Динамічні змінні чудово підходять, щоб передавати контекст у викликаний код без явного аргументу.
