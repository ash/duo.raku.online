У частині «Основи» ви познайомилися з [_мульти-функціями_](/uk/essentials/more-on-functions/multi-functions). Це кілька підпрограм з однаковим іменем. Raku вибирає потрібну, дивлячись на типи аргументів. Це називають _множинною диспетчеризацією_.

Досі Raku вибирав за _типом_ аргументів. Речення `where` дозволяє піти далі й вибирати ще й за _значенням_. Ви пишете його після параметра, і воно містить умову. Аргумент мусить відповідати цій умові, інакше цього кандидата не виберуть:

```raku
multi sub info(Int $n where $n < 0)  { say "$n is negative" }
multi sub info(Int $n where $n == 0) { say "$n is zero" }
multi sub info(Int $n where $n > 0)  { say "$n is positive" }

info(-5);
info(0);
info(7);
```

Кожен виклик запускає кандидата, умова якого істинна для цього значення:

```
-5 is negative
0 is zero
7 is positive
```

Якщо дивитися лише на типи, усі три кандидати мають однакову сигнатуру: один `Int`. Тож без речень `where` вони б конфліктували. Умови роблять їх відмінними один від одного.

## Базовий випадок для рекурсії

Часто `where` використовують для точки зупинки рекурсії. Ця точка отримує власного кандидата. Ось знову факторіал, тепер у вигляді двох мульти-підпрограм:

```raku
multi sub fact(Int $n where $n <= 1) { 1 }
multi sub fact(Int $n)               { $n * fact($n - 1) }

say fact(5); # 120
```

Перший кандидат обробляє базовий випадок, коли `$n` дорівнює `1` або менше. Він просто повертає `1`. Кожне інше значення йде до другого кандидата. Той знову викликає `fact` із меншим числом. Усередині функції немає жодного `if`. Вибір між базовим випадком і рекурсивним кроком робить диспетчер.
