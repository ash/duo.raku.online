Коли ви викликаєте метод чи підпрограму, ви зазвичай берете аргументи в дужки: `@a.grep(* > 5)`. У Raku є й друга форма. Ви ставите після імені **двокрапку**. Тоді все, що йде після неї, стає списком аргументів. Дужки зовсім не потрібні:

```raku
say (1..10).grep: * %% 2; # (2 4 6 8 10)
```

Двокрапка в `grep:` виконує ту саму роботу, що й дужки. Тож `(1..10).grep: * %% 2` означає точно `(1..10).grep(* %% 2)`. Одну форму завжди можна замінити іншою:

```raku
say <a b c>.join('-'); # a-b-c
say <a b c>.join: '-'; # a-b-c
```

Форма з двокрапкою найкраще підходить для методів, які приймають **блок** або вираз [Whatever](/uk/advanced/whatever). Це тому, що вона прибирає один рівень дужок у дужках. Порівняйте:

```raku
my @a = 3, 1, 2;

say @a.sort({ $^b <=> $^a }); # дужки навколо блоку
say @a.sort: { $^b <=> $^a }; # двокрапка — закривальну дужку шукати не треба
```

Обидва рядки виводять `(3 2 1)`, але версію з двокрапкою легше читати. Особливо це помітно, коли блок довгий.

Ви вже використовуєте виклики без дужок зі списковими операторами, як-от `say 1, 2, 3`. Там `say` бере все, що йде після нього, як свої аргументи. Форма з двокрапкою — те саме для викликів методів. Є одне правило, яке варто запам'ятати. Форма з двокрапкою бере **решту оператора** як свої аргументи. Тож вона має стояти в **кінці** ланцюжка викликів. Саме тому працює `('a' .. 'z')».uc».ord.grep: 60 < * < 70`. Тут `grep` — останній виклик, і після нього в ланцюжку нічого немає. Якщо потрібно викликати ще методи, використайте натомість форму з дужками. Або згрупуйте частини всього виразу, щоб було зрозуміло:

```raku
say (('a' .. 'z')».uc».ord.grep: 60 < * < 70)».chr # (A B C D E)
```

Є одна річ, з якою варто бути обережним. Не поєднуйте двокрапку **й** дужки, як у `.grep:( … )`. Такий запис конфліктує з `:( … )` — синтаксисом літерала сигнатури. Тож Raku не може прочитати цей код. Використовуйте або `.grep( … )`, або `.grep: …`. Беріть щось одне, а не обидва разом.
