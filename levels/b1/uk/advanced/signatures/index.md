У частині «Основи» ви [визначали підпрограми з позиційними та іменованими параметрами](/uk/essentials/functions). Ви також давали параметрам типові значення. Список параметрів називають _сигнатурою_. Цей розділ показує ще дві речі, які вміє сигнатура. Вона може зробити параметр необов'язковим і може збирати будь-яку кількість зайвих аргументів.

## Необов'язкові параметри

Параметр, після якого стоїть знак питання, — _необов'язковий_. Це означає, що той, хто викликає, може його пропустити. У такому разі параметр невизначений. Тож ви можете дати йому запасне значення за допомогою оператора «визначене або» `//`:

```raku
sub greet($name, $greeting?) {
    my $g = $greeting // 'Hello';
    say "$g, $name!";
}

greet('Anna');           # Hello, Anna!
greet('Anna', 'Hi');     # Hi, Anna!
```

Коли `greet` викликано з одним аргументом, `$greeting` невизначений. Тож `//` використовує замість нього `'Hello'`.

## Всеїдні параметри

Параметр, позначений `*`, — _всеїдний_. Він бере всі аргументи, що залишилися. Всеїдний масив, який записують як `*@`, збирає будь-яку кількість позиційних аргументів у масив:

```raku
sub count-them(*@items) {
    say @items.elems;
}

count-them(1, 2, 3, 4); # 4
count-them('a', 'b');   # 2
```

Можна поєднувати звичайні параметри із всеїдним. Сталі параметри отримують свої значення першими. Усе, що лишилося, потрапляє у всеїдний масив:

```raku
sub titles($name, *@titles) {
    say "$name has {@titles.elems} title(s)";
}

titles('Anna', 'Dr', 'Prof'); # Anna has 2 title(s)
```

Всеїдний хеш працює так само. Його записують як `*%`, і він збирає всі зайві іменовані аргументи в хеш:

```raku
sub register($name, *%options) {
    say "$name: {%options.elems} option(s)";
    say "role is %options<role>";
}

register('Anna', role => 'admin', active => True);
```

Два іменовані аргументи стають ключами в `%options`, тож програма виводить:

```
Anna: 2 option(s)
role is admin
```
