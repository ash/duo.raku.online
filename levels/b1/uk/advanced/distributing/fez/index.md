Попередня тема познайомила вас із `fez`, інструментом, який завантажує дистрибутиви в екосистему Raku. Використовувати `fez` не обов'язково, бо є й інші способи публікації. Але це найпоширеніший вибір. Крім того, він уміє більше, ніж просто завантажувати. Він може підготувати для вас новий дистрибутив і керувати вашим обліковим записом автора. Встановіть його через `zef`:

```
zef install fez
```

## Започаткування дистрибутива

Ви можете створити `META6.json` і каталоги `lib/` та `t/` вручну. Або ви можете доручити `fez` підготувати їх за вас:

```
fez init My::Greeting
```

`fez init` створює новий дистрибутив, на якому можна будувати далі. Це каталог проєкту з готовим `META6.json` і стандартною структурою. Тож ви можете одразу писати код під `lib/` і тести під `t/`. Вам не треба самим готувати файл метаданих.

## Реєстрація та вхід

Для публікації потрібен обліковий запис в екосистемі. Ви створюєте його один раз через `fez register`, який запитує ім'я користувача, електронну пошту й пароль. Потім ви входите через `fez login`. Він зберігає ваш ключ, щоб наступні команди знали, хто ви:

```
fez register
fez login
```

Ваше ім'я користувача важливе. У `META6.json` дистрибутива має бути поле `auth` зі значенням `zef:<username>`. Саме так екосистема знає, що завантаження справді від вас.

## Завантаження

Коли у вас є обліковий запис і дистрибутив готовий, запустіть `fez upload`. Він пакує поточний каталог і надсилає його:

```
fez upload
```

Після цього будь-хто може встановити його за іменем через `zef install My::Greeting`. Кожну версію можна завантажити лише один раз. Тож не забудьте збільшити `version` у `META6.json`, перш ніж публікувати оновлення.

## Інші корисні команди

Ось ще кілька команд `fez`, які вам знадобляться:

* `fez review` — перевірити дистрибутив на можливі проблеми, перш ніж завантажити його;
* `fez list` — показати дистрибутиви, які ви вже опублікували;
* `fez refresh` — знову зібрати `META6.json` з файлів, які зараз лежать на диску.

> Усім цим командам потрібні встановлений `fez` і з'єднання з мережею. Усім командам після `init` також потрібен обліковий запис в екосистемі.
