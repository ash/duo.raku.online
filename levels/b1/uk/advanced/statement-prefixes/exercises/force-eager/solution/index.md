Ось один із можливих розв'язків.

## Код

```raku
say (1 .. Inf).is-lazy;
say (eager 1..3).is-lazy;
say (lazy 1..3).is-lazy;
```

🦋 Вихідний код можна знайти у файлі [force-eager.raku](https://github.com/ash/raku-course/blob/master/exercises/advanced/statement-prefixes/force-eager.raku).

## Вивід

```
True
False
True
```

## Коментарі

1. Діапазон до `Inf` неможливо обчислити весь одразу, тож він лінивий. `.is-lazy` повертає `True`.

1. Префікс `eager` змушує Raku створити список одразу. Тож результат більше не лінивий. `.is-lazy` повертає `False`. Це пряма протилежність до того, щоб позначити список як `lazy`.

1. Не використовуйте `eager` з діапазоном, який не має кінця. `eager 1 .. Inf` намагається обчислити кожен елемент одразу. Тож програма просто зависає і бере дедалі більше пам'яті, доки її не вб'ють. `eager` безпечний лише для списків, про які ви знаєте, що вони скінченні.

1. Зворотне теж працює. `lazy 1..3` позначає як лінивий навіть короткий скінченний діапазон, тож `.is-lazy` повертає `True`. Префікс ставить прапорець лінивості, хоч би який малий був список. Список не мусить бути нескінченним, щоб бути лінивим.
