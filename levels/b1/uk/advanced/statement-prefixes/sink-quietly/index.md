Ще два префікси стосуються виконання коду заради його ефектів, а не заради значення.

Префікс `sink` виконує щось у _контексті стоку_, тобто лише заради побічних ефектів. Результат викидається. Це корисно, коли ви хочете змусити ліниву операцію виконатися:

```raku
sink (1..3).map({ print "$_ " });
print "\n"; # 1 2 3
```

Тут `map` виконується лише заради друку, який він робить. `sink` дбає, щоб він справді виконався, а потім викидає отриманий список. Якщо ніщо його не змушує, лінивий `map` може взагалі не виконатися. Так буває, коли його результат ніде не використовується.

Префікс `quietly` виконує блок із **вимкненими попередженнями**. Код, який зазвичай друкує попередження в потік помилок, мовчить:

```raku
my $value;
quietly {
    say $value + 1; # 1, без попередження "uninitialized value"
}
```

Якщо додати `1` до невизначеного `$value`, зазвичай з'являється попередження про неініціалізоване значення. Усередині `quietly` це попередження приховане. Використовуйте його, коли знаєте, що якийсь код дає попередження, і не хочете цього шуму. Але робіть це рідко, бо попередження зазвичай вказують на справжню помилку.
