Ще два контексти вирішують, чи є щось **списком**, чи одним **елементом**. Список має кілька значень. На цій різниці побудовані сигіли `@` та `$`.

У _списковому контексті_ масив розгортається у свої елементи. Цикл `for` ставить свій аргумент у списковий контекст, тож проходить по кожному елементу:

```raku
my @a = 1, 2, 3;

my $count = 0;
$count++ for @a;
say $count; # 3
```

У _штучному контексті_ той самий масив поводиться як одне-єдине значення. Контекстуалізатор `$( … )` задає штучний контекст. Тож тепер цикл бачить лише одну річ і виконується один раз:

```raku
my @a = 1, 2, 3;

my $count = 0;
$count++ for $(@a);
say $count; # 1
```

Це пояснює, що стається, коли ви присвоюєте масив скаляру. Масив пакується в один елемент, а його елементи не копіюються. Причина в тому, що `my $x = @a` ставить `@a` у штучний контекст. Зверніть увагу, що цей один елемент може бути іншим контейнером із багатьма елементами всередині:

```raku
my @a = 1, 2, 3;

my $var = @a;
say $var;      # [1 2 3]
say $var.WHAT; # (Array)
```

Змінна `$var` — це скалярний контейнер, тож тепер вона містить один об'єкт. Цей об'єкт — `Array`. Це легко довести. Використайте `$var` як своєрідне посилання на масив, як це назвали б в інших мовах:

```raku
say $var[1]; # 2
```

Його пара, контекстуалізатор `@( … )`, робить протилежне й задає списковий контекст.

Є ще _контекст стоку_ (sink context). Це контекст оператора, значення якого викидається. Наприклад, рядок коду може існувати лише заради побічного ефекту. Іноді значення в контексті стоку не робить нічого корисного. Тоді Raku може попередити про «useless use». Це корисна підказка, що ви забули використати результат.

Коли ви обираєте сигіл, `$` чи `@`, ви насправді обираєте контекст. Де потрібно, контекстуалізатори `$( )` та `@( )` дозволяють його змінити.
