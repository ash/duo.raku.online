Ви завантажуєте інструменти тестування через `use Test`. Найпростіша перевірка — `ok`, яка проходить, коли її умова істинна. Кожна перевірка також може приймати опис:

```raku
use Test;

ok 1 == 1, 'one equals one';
ok 2 > 1,  'two is greater';

done-testing;
```

Якщо її запустити, вона виводить таке у стандартному форматі тестів під назвою _TAP_:

```
ok 1 - one equals one
ok 2 - two is greater
1..2
```

Кожну перевірку, яка пройшла, показано як `ok` з її номером та описом. Невдала перевірка показала б `not ok`. Останній рядок, `1..2`, — це _план_, який каже, скільки тестів виконалося. Виклик `done-testing` у кінці виводить цей план автоматично.

Коли ви очікуєте певне значення, `is` зрозуміліший за `ok`. Якщо тест не проходить, `is` показує і очікуване значення, і фактичне:

```raku
use Test;

is 2 + 2, 4, 'addition works';

done-testing;
```

Це виводить `ok 1 - addition works`. Щоб побачити, як `is` повідомляє про проблему, дайте йому неправильне очікуване значення:

```raku
use Test;

is 2 + 2, 5, 'addition works';

done-testing;
```

Тепер перевірка не проходить, і вивід точно пояснює, що пішло не так:

```
not ok 1 - addition works
# Failed test 'addition works'
# at test.raku line 3
# expected: '5'
#      got: '4'
1..1
# You failed 1 test of 1
```

Рядок `not ok` позначає невдачу. Рядки під ним показують, що очікувалося і що програма насправді отримала. Тож коли важливе певне значення, `is` корисніший за простий `ok`.

`ok`, `is` і `done-testing` уже достатньо для корисного файлу тестів. Наступна тема додає [інші порівняння](/uk/advanced/testing/comparisons).
