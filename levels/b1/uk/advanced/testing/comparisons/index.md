Окрім `ok` та `is`, модуль `Test` має порівняння для різних видів значень. Ось найкорисніші з них:

* `is` — перевіряє, чи рівні два значення (як рядки чи числа)
* `is-deeply` — перевіряє, що дві структури даних точно рівні, разом з їхніми типами
* `like` — перевіряє, що рядок збігається з регулярним виразом
* `isnt` — проходить, коли два значення **не** рівні

`is-deeply` — правильний вибір для масивів, хешів і вкладених даних. Він точно порівнює і структуру, і тип:

```raku
use Test;

my @reversed = (1, 2, 3).reverse;
is-deeply @reversed, [3, 2, 1], 'reversed';

done-testing;
```

Це виводить:

```
ok 1 - reversed
1..1
```

`is` перетворив би значення на рядки й порівняв би їх нестрого. Але `is-deeply` вимагає, щоб структури справді збігалися. Зверніть увагу, що `done-testing` ставить план `1..1` у кінці, після перевірки.

Вам не обов'язково доручати `done-testing` рахувати тести за вас. Натомість ви можете вказати їхню кількість на початку через `plan`. Це захищає вас від файлу тестів, який зупиняється рано й тихо пропускає деякі перевірки:

```raku
use Test;

plan 2;
ok True,  'first';
ok 1 < 2, 'second';
```

Цього разу план іде **першим**, перед результатами:

```
1..2
ok 1 - first
ok 2 - second
```

Це і є видима відмінність від `done-testing`. `plan` виводить кількість `1..2` угорі, ще до того, як запускаються перевірки. `done-testing` натомість виводить її в самому кінці. У будь-якому разі з `plan 2` запуск очікує рівно двох тестів. Якщо запуститься менше або більше тестів, набір тестів вважатиметься невдалим. Використовуйте `plan`, коли кількість тестів незмінна й відома. Використовуйте `done-testing`, коли простіше дати фреймворку тестування порахувати їх.
